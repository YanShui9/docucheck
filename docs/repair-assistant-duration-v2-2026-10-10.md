# 交期规则及旧报告兼容修复

## 实际失败与范围

助手多轮验收的合成报价含“订单确认后18个自然日内交付”，已确认要求为订单确认后14个自然日。此前真实审查两次均 `partial / coverage_incomplete`：模型使用单位“自然日”时，中文量词“个”阻止原文数值验证；去除该问题后，句尾“交付”又可能被误识别为第二个起算事件。本轮修复有限交期语义，不修改原有用户任务或已确认清单。

另一拒绝原因是模型引用不同表格行组合品目和数量，命中 `evidence_relationship`。本轮保留同一行及明确型号绑定守卫，不能为了让验收通过接受任意跨行拼接。修复后的真实审查仍需另行复验。

## 修改内容

- duration 允许“18个自然日”“18个工作日”的中文量词，并保留自然日/工作日差别；普通 numeric/money 的单位校验保持原契约。
- “交付期限”“交付时间”“交付周期”是指标标签；句尾“内交付/前交付”是终点。独立起算条件与后置付款条件仍被检查，多个起算点转人工确认。
- 需求原文与供应商事实使用相同起算条件检查；复杂或冲突需求不能变成可执行自动规则。
- 新结果为 `dynamic-rules-v2`；旧 v1 的事实、报告、manifest、导出和修正按其原版语义重放。缓存摘要包含规则版本，新审查不能直接消费旧版抽取缓存。
- 完整重审先校验旧报告，再按新版重校验人工备选事实。无法转换时返回 `partial / manual_alternative_revalidation_required`，没有正式检查；不会丢掉旧备选后悄悄发布新结果。
- 时间工具调用后的模型提示限定为日期、星期、时区与通用原则，要求不自行举截止日计算例子。仍为按需调用；这是提示约束，尚不是确定性日期计算工具，也不能保证所有模型输出都遵循。

## 验证与交付状态

新增中文量词用例先出现4个失败；指标标签用例先出现2个失败。修复后四模块221项通过。独立只读复查确认旧 v1 的18组差分保持，并验证真实旧事实“苹果交期18自然日前交付”无法迁移时正确拒绝、全部检查非正式、抽取0调用。该实际反例已固定为单测并通过。

最终应用代码完整离线门禁为 **1358 passed / 41 skipped / 网络尝试0**，Ruff 与 pip check 通过；全量收集后将转换拒绝测试从故障注入替换为上述真实 v1 语义反例，并单独重跑1项通过，未再修改应用代码。运行中服务同步结果在后续应用记录中补充。历史 `1351 passed / 41 skipped` 属于本轮中间代码，不能替代最终门禁。浏览器重新登录后，临时 OIDC 端口改变 issuer，原工作区不显示；这属于身份地址迁移隔离，应恢复原 issuer 端口，不应直接修改成员权限或关闭认证。

## 边界

这是有限语法验证，不是通用中文时间理解；节假日、具体截止日期、任意表格跨行品目继承均不在本修复内。新结果发布后，直接把程序回退为只认识 v1 的旧版本无法读取 v2 报告；回退需同时使用兼容读程序，或在受控停机下恢复匹配的数据备份。没有数据库迁移、向量重建或依赖安装。
