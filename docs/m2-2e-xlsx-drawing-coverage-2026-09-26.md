# M2-2e：XLSX 图片与图表覆盖检查（2026-09-26）

本步处理工作表单元格已读取、但嵌入图片或图表被忽略后仍返回 `complete` 的风险。只修改后端 XLSX 解析和离线测试；没有调用模型 API、启动 Docker、安装依赖或修改前端。M2-2 整体仍未验收。

## 第一步：复现误判

测试分别生成两份 XLSX：一份在“报价”表 D4 锚定含 `Installed RAM 32 GB` 的图片，另一份在同一位置放图表；表内另有 `A1=已装内存`、`B1=16 GB`。修正前，`ReadOnlyWorksheet.iter_rows()` 只返回单元格，两个文件都被误判为 `complete`。先运行失败回归，确认两种遗漏。

## 第二步：修正解析覆盖

`parse_xlsx` 已有一次工作表 XML 预扫描，用来识别合并单元格及错误范围声明。本步在同一次扫描中识别工作表实际引用的 `<drawing r:id="…">`，记录 `sheet:<工作表名>:drawing_unverified:<关系 ID>`，并将文件标为 `partial`。现有单元格仍照常读取、保留原位置；不会因 ZIP 中存在未被工作表引用的绘图资源而改变状态。解析版本增加 `/drawing:1`，新快照中的证据 ID 随版本变化。

该问题记录的是工作表名及绘图关系 ID，暂不提供图片或图表的单元格锚点，也不识别其中的文字或数值。

## 第三步：离线验证

图片和图表两项新增测试先在旧逻辑下失败，修正后通过。后端全套测试 **127/127 项通过**，全目录 Ruff 与 `pip check` 通过。原有普通 XLSX 仍为 `complete`。本步没有重新运行真实模型对话。

## 边界与下一步

`partial` 表示现有单元格证据不足以证明绘图内容已覆盖，不表示绘图一定包含采购参数；装饰图片或图表也会保守地触发。批注及旧式绘图、隐藏行列、其他不支持结构和任务级限额仍需处理。下一小步拟检查 XLSX 批注及旧式绘图；开始前仍按一次一个小步骤核对范围。
