# 面试演示：十分钟采购初审

日期：2026-10-03。启动步骤见[复现手册](reproduction.md)，原理与追问见[架构讲述](architecture-and-interview.md)。本文件是演示操作脚本，不是“已现场执行”的记录。

## 三种演示，先说明当前用哪一种

| 形式 | 操作 | 可以证明的成果 |
| --- | --- | --- |
| 离线工程回归 | verify_offline、Vitest、构建、ZIP 验证 | 已实现的约束、受控工具、来源验证、状态机、权限和恢复测试；无真实模型请求。 |
| 历史真实运行回放 | 查看归档原件、观察 JSON、版本/质量/性能报告，或已有数据库 Run | 对应版本确实执行过的结果；不能称刚刚重新推理。 |
| 授权的现场模型实演 | 启动 OIDC/解析/API/worker/前端，上传新 Case 后问答 | 当场实际处理、调用模型、生成带原文依据的结果；会计费，失败如实展示。 |

CLI `agent_demo` 读取经哈希核验的开发解析缓存，不能用它证明现场上传后的全链路。下面采用现有工作台和正式上传接口。网络或模型不可用时切换历史回放，并明确说出切换原因。

## 演示前准备

- 恢复归档至新目录，找到 `data/m5-candidates/inputs/m5-c01/` 的五份合成资料；只上传 inputs 原件，不上传 gold/报告。
- 检查服务健康、迁移头、解析终端、登录和模型配置。账号/口令只在本机使用，不投屏 `.env`、Keycloak 管理界面密钥、Authorization 头。
- 若准备现场提问，先得到资料发送和付费授权；每个 Run 有本地调用/token/时间预算，不反复重试失败任务来挑一个成功画面。
- 已存在的历史结果可先查看；现场验证必须新建 Case。处理中的 partial/failed/unknown 保留，不能改写为 completed。

## 0:00–1:00：讲清业务

“需求书、供应商报价和规格书经常分散且互相矛盾。系统让采购人员上传资料、提问，Agent 找来源、提取事实，规则按统一口径比较八个字段。审查者能回到原件，并只修正有原文支持的事实。”

说明这是笔记本采购初审，最多三家供应商；它不作法律意见、综合中标排序或自动采购决策。

## 1:00–3:00：登录、建项目、上传并解析

以 alice 登录，创建演示项目和新 Case。先上传 requirements.pdf，角色为需求；再按下表关联报价/规格：

| 原件 | 供应商 | 型号 |
| --- | --- | --- |
| vendor-a-quote.xlsx / vendor-a-spec.pdf | vendor-a | MC-C01-1 |
| vendor-b-quote.xlsx / vendor-b-spec.pdf | vendor-b | MC-C01-2 |

每次上传生成新版本；等待五份资料的解析状态变为 complete。截图/复杂结构若 partial，应解释“覆盖未完成”，不要提前给出正式满足结论。演示解析进程与队列是异步服务，不是浏览器同步等待几十秒的请求。

## 3:00–5:00：完整审查和八字段矩阵

选择 thorough，问：`请完整审查全部供应商的八项指标，并列出每家每项结果与来源。`

`m5-c01` 的开发参考如下；这是拟定 gold 经 AI 原文复核的结果，不是独立封存集：

| 字段 | vendor-a | vendor-b |
| --- | --- | --- |
| 内存 | 资料冲突 | 满足 |
| 存储 | 满足 | 不满足 |
| 屏幕尺寸 | 满足 | 不满足 |
| 重量 | 不满足 | 满足 |
| 质保 | 证据不足 | 满足 |
| 采购数量 | 满足 | 不满足 |
| 单价 | 满足 | 不满足 |
| 交付期限 | 满足 | 满足 |

展示矩阵中的处理状态和业务状态是两回事：completed 可以包含冲突/不满足；partial 不能冒充证据不足。说明交期按供应商承诺核验，承诺上限超过同口径需求上限即不满足。

## 5:00–6:30：追问并回到证据

问：`供应商 A 的内存为什么冲突？你根据哪两处判断？`

点击对应引用，展示同一供应商/型号的报价单元格与规格 PDF 页码/bbox，再查看需求阈值。追问不得读 vendor-b 的私有来源来回答 vendor-a；服务器将证据绑定 Case、快照、文档、供应商与型号。说明 RAG 帮助找到相关原文，但正式缺项要扫描全部适用资料，不能因为 top-k 没命中就说没有。

## 6:30–8:30：事实修正、冲突和历史

普通已正确抽取的事实无需为了演示改成错误值。可以选择一个事实输入原文不支持的值，确认修正被拒绝，且旧原件/结果保留。

若需要展示合法修正，使用归档内**单独的合成修正案例**：`data/m5-b-live-boundaries-20261002-source-handles/inputs/`。该报价 `报价明细!B8` 原文同时写“标称 SSD 512 GB / 标称 SSD 1 TB”。新 Case 上传该目录的需求、报价、规格；从原文支持的已抽取 512 GB 改为 1000 GB（项目标称 TB=1000GB），写明原文支持理由。

该案例不是未经改动的 m5-c06，也不计入原 104 格质量分母。合法修正生成新快照，保留旧事实；两值均有支持时保留冲突并显示需人工复核。规则重算不调用模型。若现场抽取没有给出可修正的 512 GB，回放已测的修正记录，不臆造或覆盖事实来迁就演示。

切换历史快照，展示旧结果、旧事实与修正审计仍可读。历史结果导出有历史/非正式标记，不因用户修正而悄悄变成新结论。

## 8:30–10:00：导出、隔离与结果边界

选择有结构化结果的 Run，导出 JSON/XLSX；核对供应商、八字段、状态、原文位置、输入版本与复核标记。两个格式来自同一导出数据构造器。

若现场时间允许，以 bob 登录验证未加入项目时不可读取 alice 的资料；账号名称不决定权限，成员 owner/editor/viewer 决定写读能力。跨项目 API 越权负例有自动测试，不能把单个界面按钮隐藏当作授权实现。

最后展示[M5-B 原始报告](m5-b-development-validation-2026-10-03.md)：12/12 任务、104/104 状态、89/89 必要证据、危险误判满足 0；固定五文件 9/10 成功且不超过 120 秒，1 次驱动中断保留失败。资料是合成、作者已见、AI 复核，独立封存 0，实际账单/缓存拆分未知。不要声称任意采购文件或生产流量都有同样质量。

## 演示后

保存新 Case/Run ID、版本、处理终态、调用/token 和异常；保留完整失败。需要停止付费执行时停 worker/dispatcher；Case 删除会由 cleaner 物理清理，不把删除按钮作为演示结束的默认操作。
