# 十分钟演示：从采购需求到原文复核

更新日期：2026-10-13。这是操作指南，不代表本文已执行一次新的真实模型验收。当前有待修复缺陷，稳定面试版本尚未通过；按[收尾计划](superpowers/plans/2026-10-13-project-consolidation.md)先修复再重演。现场只使用合成资料。

项目面向多品类采购。苹果/T恤混合报价、手机数量/交期与人工确认资料仅为可替换的演示样例，资料身份和参考结果见收尾计划；固定数据与脚本用于复现一次演示，不限制产品品类或替代多品类评测。以下十分钟流程保留为公开单苹果的简化模板；E 阶段重新实测所选样例。本步没有启动服务或产生模型调用。

## 0:00–1:00：业务与范围

说明场景：“买方提出要求，供应商给出报价和承诺。系统把动态指标与原文对应起来，展示哪些满足、哪些冲突、哪些还需要人工确认。”

指标随任务变化；固定设备八字段仅用于早期回归样例。系统不代替人工采购决策，也不自动确认买方要求。

## 1:00–3:00：聊天整理需求并确认

输入：`我要采购苹果，数量至少20箱，含税单价不超过100元/箱，请整理审查要求。`

查看候选中的品目、数量、单价、含税口径与来源。打开清单，确认候选正确后保存草稿，再明确确认。展示两步协议，说明“模型生成”“保存”和“确认生效”是三个不同状态。

可追加一句 `再加交期，但我还没确定多少天`，查看是否保留待核对项，不能让助手编造一个交付天数。为保证演示时间，可只确认数量和单价。

## 3:00–5:00：上传资料与原文问答

上传 `synthetic-apple-quote.xlsx`，角色为供应商报价，供应商名称填写“合成苹果供应商甲”。等待解析完成；资料升版后，按界面提示重新保存并确认适用清单。

在“资料关联采购品目”入口选择苹果，核对原文范围和来源，再明确保存确认。只有资料确实属于单品目时才选择整份单品声明；对应关系不代替供应商承诺。

先问：`这份报价承诺的数量和含税单价是多少？请引用原文。`

原件参考：`采购资料!C3` 为 25 箱，`采购资料!C4` 为 90 元/箱且含税。点击来源，回到工作表与单元格；检查需求原文没有被当作供应商承诺。问 `单价含税吗？`，验证同一任务的上下文追问。

## 5:00–7:00：正式审查与报告

在确认版本有效、资料完成的前提下，发起：`请按已确认的清单审查这家供应商，并列出每项结果与来源。`

简单同口径数值的参考比较是 25≥20、90≤100；若提取、关联或覆盖尚未明确，结果应保留人工核对或未完成，不能为了演示强改为满足。首页旧报告展示对应验收任务两项满足；新的运行以当场结果和原因说明为准。

区分处理状态与业务状态：completed 可以包含不满足、冲突或人工确认；partial 不能冒充完整扫描后的证据不足。

最新显式品目对应前端与指定合成闭环已交付；混合采购样例用对应范围展示不同品目的隔离，绑定使用实际原文范围。普通授权浏览不选择品目时，不能声称自然语言已自动提供硬隔离。

## 7:00–9:00：人工复核、历史与导出

选择一条可修正事实，输入原文不支持的值，查看拒绝与原值保持；正确事实不必为了展示改成错误值。合法修正须引用同一原文支持的新值，并保留审计和历史版本。

从报告导出 Excel / JSON，核对指标、供应商、状态、来源及资料版本。历史报告应有历史或非正式标记。没有结构化审查结果的普通聊天和摘录不能导出为正式审查。

## 9:00–10:00：解释架构与证据

展示[架构说明](architecture-and-interview.md)中的模型 / 规则分工、混合检索、分阶段上下文、Outbox 和 fence。

打开[评估说明](evaluation.md)：离线回归、服务实连与历史真实模型开发集分开报告。104/104 来自固定字段合成开发集，独立封存为 0，当前多品类质量和实际账单还没有完整验收。

若模型不可用，明确切换到公开截图、已有结果和源码回放；失败本身可以展示错误码、状态、来源保护和显式重试边界。
