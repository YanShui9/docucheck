## 2. 离线确认的金额表头缺口

当前 v12 在已验证的品目关联范围中支持有限单价别称，但漏掉了“不含税单价”。用相同表格结构构造、不访问数据库或模型的反例结果：

| 价格行 | 当前校验结果 |
| --- | --- |
| 单价 25 元/箱 | 通过，税口径未说明 |
| 含税单价 25 元/箱 | 通过，含税 |
| 不含税单价 25 元/箱 | 拒绝：指标未匹配 |
| 未含税单价 25 元/箱 | 拒绝：指标未匹配 |
| 税前单价 25 元/箱 | 拒绝：指标未匹配 |

对应代码：[facts.py](../backend/app/criteria/facts.py) 的 `_fact_clause`，以及需要一致处理的 [validation.py](../backend/app/criteria/validation.py) 的 `strict_source_comparator`。

但原报价还有另一行“税费口径：含税”，与“不含税单价”存在矛盾。当前主引用要求同一行连续单元格，不能把两个业务行随意拼成一段原文。独立材料来源组当前仅支持材料存在性，不支持金额税说明。

因此，补齐表头别称能够修复已复现的识别缺口，却不足以关闭这份报价的税口径问题。若只采信价格行而遗漏另一行说明，可能错误判为满足。

## 4. 方案取舍

| 方案 | 收益和局限 |
| --- | --- |
| 只补单价别称 | 改动小，但仍可能遗漏独立税说明，不能独立关闭本例 |
| 金额行与独立税说明分别验证，再核对适用范围（推荐） | 保留独立出处，能表达冲突及归属不明；需要新增有界金额来源协议和规则版本 |
| 放宽为任意跨行拼接 | 容易混入别的品目、供应商或价格，破坏现有来源守卫，不采用 |

## 5. 推荐下一单步：有界金额识别与税口径核对

以下是待用户确认的行为范围，具体字段协议在确认后制定实施计划：

1. 在已确认关联的供应商、品目、文件和版本范围内识别明确单价表述；补齐不含税、未含税、税前等有限别称。预算、总价、参考价不当作承诺单价。
2. 价格行、税口径说明分别保留原文与位置，不靠任意跨行拼接。正式审查的完整覆盖需包括适用的税说明，不能以检索未命中认定没有冲突。
3. 仅当来源关系可以验证时，才把独立说明用于该金额。明确矛盾须展示两处来源并阻止自动判满足；多个价格、多个品目或归属不明时保留待人工确认。
4. 清楚区分“审查流程没有完成”和“已完成审查但需要人工确认”；来源校验失败不能伪装成业务结论。
5. 使用新规则身份隔离本次语义，旧版本事实、报告和缓存继续按原协议读取。本步不增加自动模型重试次数。

### 验收标准

- 无矛盾且来源完整的“25 CNY/箱、不含税”可与相同口径的上限 25 比较；26 应判不满足。
- 本例“不含税单价”与“税费口径：含税”都被保留并展示，不能只因 25≤25 判满足；适用关系确认后给出冲突结论，关系无法验证时待人工确认并说明原因。
- 币种、单位、税口径缺失或不一致不擅自换算；预算/总价/参考价等反例继续拒绝。
- 多品目、多供应商、不同文件版本、未确认关联不得串用税说明；同一文件本身不构成适用关系证明。
- 新来源结构贯穿抽取、事实校验、缓存、历史回读及 API/JSON/XLSX，缺失或篡改来源时拒绝。旧规则报告回归不变。
- 先用不调用真实模型的反例和必要数据库测试验证，再单独记录部署及真实报价复测；离线通过不等于本例真实审查已关闭。
