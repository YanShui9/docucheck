# M3-11a：为人工修正保存可复核事实集

日期：2026-09-29。用户选择只修正有原文依据的提取事实。本步是人工修正的后端基础；尚无修正提交 API、新快照或自动规则重算。

## 已实现

- Agent Run 的 `memory_json` 升至版本 2，保留版本 1 读取兼容。除核验结果外，保存当前运行每个供应商、字段的最新已验证事实集及扫描范围。数值保存为十进制字符串。
- 事实集最多 24 组，每组最多 256 个事实、25,000 个扫描证据 ID，总编码不超过 512 KiB。超限时只保存原有结果，标记 `fact_sets_available=false`，不保存部分事实集。
- 跨进程恢复时，重新核对快照指纹、供应商、证据归属、原文中的数字和单位、正规化结果、事实集标识及完整扫描声明。任一校验失败则返回 `memory_scope`，且不会把部分恢复状态交给 Agent。
- 这是服务端数据的保守恢复校验。`fact_sets_available=true` 不表示业务证据覆盖完整；事实集本身的 `complete` 和 `coverage_issues` 仍分别生效。

## 验收

- `python.exe -m pytest backend/tests -q`：`379 passed, 10 skipped`。包含字段与内存事实集往返、版本 1 兼容、来源/值篡改拒绝、完整扫描声明校验和超限降级。
- `ruff check backend evals`、`pip check`、`git diff --check` 通过。
- 本步没有迁移数据库、运行 Docker 操作或调用 DeepSeek。真实 MySQL 中 Run JSON 的新字段尚未做独立集成验收。
