# 上下文 A1：完整业务请求计量与拒绝诊断

日期：2026-10-21。实施基线 `fd8cfb7db55171968a441eec1c4b78b79df962d5`，分支 `codex/context-request-diagnostics`。本记录在隔离工作区保存；A1 源码与离线验收完成，随独立本地提交保存。

## 变更和原因

聊天纠错、动态正式抽取、格式修复、事实修复和旧八字段流程原先在预算检查后才创建模型事件。请求被提前拒绝时，无法从事件中还原该次请求的大小、限制或修复阶段。

新增 `backend/app/agent/context_usage.py`，三条模型调用路径先计量和创建事件，再请求原有 `Budget.reserve()`。资料问答整理到最后一个来源窗口仍放不下、清单规则读取或编辑范围组装后放不下时，也记录最终被拒绝的请求，不额外预留或增加决策次数。原样保留预算判断、范围错误码及处理状态；本地拒绝为 `rejected`、`provider_called=false`，明确记录 `context_budget`、`token_budget` 或原有清单范围错误。预留通过后在紧邻 Provider 方法调用的位置标记 true；这个标记不保证网络已经发送或服务商已经收到。

记录字段包括：

- 模型配置窗口：token 单位；不证明第三方接口的实际长输入能力。
- 最终业务消息与工具定义的旧估算值、工具定义字节数、旧单次限制及旧累计剩余额度。旧估算仍按序列化 UTF-8 加固定开销计算，不宣称精确 token 或网络请求大小。
- 本次要求的输出额度与计划预留输出额度；拒绝发生时没有实际预留，字段因此命名 `output_planned_tokens`。
- 请求阶段、格式/事实修复标记、消息与工具定义指纹；不保存请求原文或工具参数。

`safe_trace_events()` 白名单过滤新字段，拒绝未知版本、错误类型、布尔冒充数字、越界数字、任意文本和非法指纹。仅旧单次限制接受有界负数，以保留“输出预留已超过窗口”的诊断。旧事件没有新字段时保持原结构，沿用现有 Run 事务、权限、版本及 attempt/fence 保护，没有新增表或迁移。

## 验证

环境：Windows、PowerShell 7.6.5，Conda `docucheck` 的 Python 3.12.14，沿用已安装依赖。定向测试和全量均启用 `scripts.offline_guard`；不读取 `.env` 或访问业务数据库，不启动服务、不安装依赖，不调用真实模型。

隔离工作区第一次基线出现 17 项旧样例失败，原因为 Git 的 CRLF 转换使 4 个 MinerU 缓存 JSON 的字节摘要变化。核对 Git 原始 blob 均符合 manifest 后，在隔离工作区按 blob 恢复原始字节；没有放宽摘要校验或修改样例语义。修复工作区准备后基线 **102 passed，网络 0**。

失败回归先在原实现验证：新计量模块缺失导致导入失败，四条实际路径分别复现“第一次请求可发出，修复请求超限但没有拒绝诊断”。自审又复现资料问答在来源窗口整理阶段直接超限，以及清单读取/编辑范围过大却无拒绝事件，补失败回归并接入相同计量。新增测试覆盖 26 项，包括单位/指纹/输入不变、上下文与累计用量拒绝、输出不足、取消/超时、已知与未知 usage、三条路径和两种修复、成功调用事件不重复、SQLite executor 落库和历史刷新、旧事件兼容、取消/快照变化及权限撤销。

首次相关回归 **237 passed，80.18 秒，网络 0**；补齐资料问答的提前拒绝后，相关 **76 passed，36.33 秒，网络 0**；最终补齐清单读取/编辑拒绝后，相关 **101 passed，49.12 秒，网络 0**，全仓 Ruff 与差异检查通过。
