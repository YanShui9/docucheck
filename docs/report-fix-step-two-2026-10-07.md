枚举规则中的 values 表示需求允许的范围，不是供应商事实输入白名单。因此允许录入原文中的范围外选项，交由后端核验是否不满足。人工规则的事实修正也不会把复杂条件变为自动可判定规则。

## 一致性与约束

- 动态 checks 与 correction audit 响应新增 payload_digest；facts 的摘要与已确认 rule 来自验证后的后端数据。
- 前端只展示绑定相同 Case/Run/snapshot/revision/确认版本且摘要一致的读取结果。并发修正导致多个读取跨版本时，清除报告并要求重新读取。
- 保存成功的首轮刷新还核对 POST 返回摘要，避免接受保存前的旧报告；若其他人又修正导致摘要更新，显式重试可以读取最新一致版本。
- 排队且没有抽取载荷时，空结果和 null 摘要可读，不能提交事实修正；历史/只读报告也不能提交。
- 后端 facts 与 audits 多次查询之间发生真实修正事务时，拒绝返回混合结果，使用原有 run_changed 错误。
- 原文、引用、供应商、品目和指标归属不能修改；保持同源支持、expected_revision、digest、幂等、Case 锁、成员权限及 needs_review 约束。保留旧事实并追加备选，不自动消除冲突。
- assistant 载荷经过原有来源验证后才参与同步；篡改或并发变更拒绝写入，不能用修正操作覆盖一个已损坏的聊天结果。
- 审计目标 ID 是既有 JSON 中的审计元数据，无数据库结构迁移和新依赖。旧审计不能唯一还原的目标不做自动补填。

异步边界参考 [Vue 官方侦听器副作用清理说明](https://vuejs.org/guide/essentials/watchers#side-effect-cleanup)。取消读取或卸载组件不能撤销后端已开始的写入，因此报告面板隔离自己的状态，App 独立跟踪已发出的修正请求。按 Run 保存不可变状态映射，使用计数跟踪同 Run 请求并保留完成状态，避免 Vue 批处理丢失中间通知；未变化的条目不会重复读取。

## 验收边界与下一组

本轮验证使用真实 Vue 组件、隔离 SQLite、真实后端契约与脚本 Provider，禁止外网调用。未启动、重建或重启 Docker/API/前端开发服务，未调用真实模型，未重复 MySQL/OIDC/浏览器端到端实连。

新增响应契约需要后端与前端一起加载本轮代码；旧后端缺少摘要或 rule 时，前端会要求重读而不会猜测或允许无类型修正。不能把源代码修复称为运行服务已经部署。

如果此前旧代码已造成 assistant-result 损坏，本轮不会自动重写历史数据来绕过验证；应保留审计，按原资料重新审查，或另做受控数据修复。
