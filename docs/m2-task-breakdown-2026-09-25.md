## M2 完成边界

一份需求与 1～3 家供应商的报价/规格书，围绕内存、存储、屏幕、重量、质保、数量、单价、交付期限回答定点问题及完整审查。每个 `(快照, 供应商, 字段)` 独立记录解析与抽取覆盖、已验证事实、五种业务状态或处理未完成，以及可定位来源。完整覆盖之前不因检索无命中或模型漏抽判“证据不足”，也不发布无证据的“满足”。先验收一家八字段，再扩三家。

M2 继续使用现有 LangGraph 单 Agent、配置化真实 Provider、检索/原文/抽取/规则工具。正式文件上传、FastAPI/MySQL/worker 接线属 M3；Vue 页面属 M4，开始任何前端设计或代码前仍须与用户单独讨论并确认规范。

## 顺序与每步验收

| 步骤 | 本步交付 | 独立验收重点 |
| --- | --- | --- |
| **M2-0 XLSX 内存结构关系** | 在内存核验中保留表头、行标签、数值单元格之间的可验证关联；候选事实可引用组合来源，校验仍回到各原始单元格 | 明确的 `A6=已装内存、B6=16 GB、规格=32 GB` 必须得出“资料冲突”；关系不明时保持未完成或待确认，绝不能误判“满足”。模型漏抽组合来源时覆盖不得标为完整。只做此步，不调用模型 API |
| **M2-1 答复引用范围** | 为核验答复绑定当前结果的供应商/字段/快照，额外引用只允许该结果适用的需求及供应商来源；记录理由相关引用 | 离线构造 A/B 两家：A 的答复加入 B 证据必须拒绝；“哪两处冲突”突出报价与规格书两处；旧 M1 两轮用例继续通过 |
| **M2-2 解析覆盖** | PDF 表格/忽略区域和 XLSX 合并/不支持结构的覆盖记录；任务级文件数、大小、页数、工作表/行列/单元格上限一致执行 | 每种不支持/缺失区域都有位置和原因；解析不全不能生成正式缺失或满足结论；七文件与 PDF 总 30 页边界可测试 |
| **M2-3 通用核验契约** | 类型化字段键、原始/标准化值、单位、限定语、型号、比较符；FactSet/CheckResult 和缓存按快照、供应商、字段隔离 | 同一来源的不同字段及三家同名字段互不污染；五业务状态与 `partial/failed` 处理状态分离；现有内存回归通过 |
| **M2-4 全量字段抽取** | 按字段、供应商、适用文档逐批扫描，分页/续批不截断；每批记录已扫描证据与失败原因 | 人工把冲突来源放到检索 top-12 之外，完整核验仍找到；任一必需批次失败时业务状态为空；模型空数组不能单独证明字段不存在 |
| **M2-5.0 内存口径补齐** | 在通用契约下复核已装/最大、GB/GiB/MiB 和严格比较语义 | 单位与限定语不明保持待确认；现有 16/32 GB 冲突及相邻单元格回归通过 |
| **M2-5.1 存储** | 标称容量与可用容量、多磁盘、GB/TB/GiB 口径 | 标称 TB 按 1000 换 GB；GiB 不混作 GB；口径不一致时不直接比较 |
| **M2-5.2 屏幕** | 尺寸单位、对角线及约数语义 | 明确 cm 按 2.54 换英寸；近似或对象不清时待确认，无隐式容差 |
| **M2-5.3 重量** | g/kg 标准化与裸机/包装区分 | g 按 1000 换 kg；包装重量不冒充设备重量 |
| **M2-5.4 质保** | 年/月期限与服务类型区分 | 年按 12 换月；“终身”和服务范围不明不擅自转为数值 |
| **M2-5.5 数量** | 正整数采购数量，套装和赠品口径 | 只比较同一计数对象；赠品不计采购数；无法确认套装关系时待确认 |
| **M2-5.6 单价** | `Decimal` 元/件、币种、含税/未税口径 | 税费、币种、计价单位不一致时不臆造汇率或税率；金额保持十进制精度 |
| **M2-5.7 交期** | 起算事件、自然日/工作日/周 | 起算事件相同才比较；自然周按 7 天，工作日不直接换自然日 |
| **M2-6 多供应商矩阵** | Agent 可针对一家或全部供应商、一个或全部字段调度；每格独立结果和未完成原因 | 先一家八字段五状态开发用例，再三家 24 格；不同供应商数值不构成资料冲突，引用不串家 |
| **M2-7 会话与执行档位** | 结构化供应商/字段指代摘要、澄清往返、`standard/thorough` 两档预算与覆盖策略 | “重量呢”继承正确供应商并重新取证；歧义进入澄清；完整审查用深入档且继续受调用、token、期限上限约束 |
| **M2-8 检索与 Agent 评测** | 开发集标注必要证据，测词法 `recall@12`、无效引用、状态混淆、调用/token/延迟 | 报告分子/分母和失败案例；若稳定漏召回，再单独设计并比较语义检索，不预设向量库；含无命中改写、提示注入、版本替换、预算耗尽 |
| **M2-9 集成验收** | 离线全链路回归与用户可执行的真实 DeepSeek 小探针，先一家再三家 | 八字段、五状态、证据定位、未完成处理逐项核对；记录真实请求数、用量和失败，不能用 Fake 结果代替真实模型结果；正式封存集与最终质量门槛留 M5 |

任务 `M2-0` 和 `M2-1` 修复 [M1 审查](m1-review-2026-09-25.md)确认的两项 P1，应先于三家与完整审查。先处理会产生错误业务结论的分列内存证据。其余步骤依赖通用证据/结果契约；七个字段规则逐项交付和测试，不一次性写完。每一步先说明本次会改哪些模块及如何验收，完成后停下核对，再进入下一步。
