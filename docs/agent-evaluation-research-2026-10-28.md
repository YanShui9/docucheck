# Agent 评测方法调研与 DocuCheck 采用决定

核查日期：2026-10-28。对象是项目级采购 Agent 评测，不是基础模型通用能力排名。

## 结论

40 个不同任务、开发/测量分组、事先固定参考答案、结果及来源验证、版本冻结和真实运行记录，符合所查一手资料中的工程评测做法，适合作为面试展示的首版评测工程。这个判断是对方案的评审，不是已经取得高分、第三方认可或面试通过保证。样本数量本身不能弥补有歧义的任务或错误的评分器。

## 对原方案的核对与修订

| 检查项 | 原方案状态 | 采用后的要求 |
| --- | --- | --- |
| 任务与实际产品相符 | 已覆盖路由、RAG、审查、记忆、安全 | 每题增加真实需求或旧失败出处；新样本不能只是换数字 |
| 正反例 | 有缺证据、安全题 | 明确应检索/无需检索，应澄清/可执行，应修改候选/禁止直接确认等成对检查 |
| 标准答案 | 先写答案及必要来源，不用产品规则生成 | 另备可通过评分器的参考 observation，证明不是不可通过的题 |
| 工具轨迹 | 原要求记录工具与参数 | 不按唯一完整调用顺序计分；仅确认、权限、来源读取等必要先决关系作为硬约束 |
| 结果验证 | 已包含落库、API、导出 | 将答案、证据、状态变更分别打分；严格任务通过外给诊断维度，不把partial局部正确算整题通过 |
| 运行隔离 | 已限定新工作区、新会话 | 每个trial独立Case/确认状态；记录索引ready和降级；冷/热缓存、环境阻塞另列 |
| 裁判可信度 | 已计划错误值等反例 | 参考解加恶意变体验证；模糊语义保持待复核，不默认通过，不声称AI复核等于人工 |
| 稳定性 | 六题各三次 | 仅报告该子集重复观测；不将最佳结果替代首轮，不称整个产品稳定性保证 |
| 统计与范围 | 已区分40任务和多轮步骤 | 开发组不混入30题主成绩；附首轮区间与固定分母，安全错误单独列 |
| 术语 | 原“离线层/真实层”可能混淆 | 固定数据集经过真实模型仍叫数据集离线评测；网络隔离测试与线上监控另区分 |
| 面试可核验性 | 已计划源码、报告和示例 | 公开合成输入/gold、失败、评分器、命令与版本；每个展示数字都能回到逐题记录 |

## 面试展示能够支持的表达

完成真实运行后，才按实际结果描述“构建采购场景 Agent 评测，覆盖任务行为、来源支持、状态一致性和安全范围；固定数据与版本，记录首轮失败并分析根因”。不预填成功率，不称生产准确率、行业领先或独立人工封存。

应能现场解释一个成功例、一个合理人工确认例、一个真实失败例，以及评分器为什么会接受或拒绝它们。教学在评测交付后进行，本报告不替代维护者本人对实现的掌握。
