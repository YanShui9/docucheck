## 本机离线复现

在已激活的 `docucheck` Conda 环境与仓库根目录执行：

```powershell
python.exe -m pytest backend/tests -q
python.exe -m ruff check backend evals
python.exe -m evals.m2_development --output data/evals/m2-lexical-001.json
python.exe -m evals.m2_agent --output data/evals/m2-agent-scripted.json
```

`evals.m2_agent` 使用代码中的脚本化 Provider；`scripted_usage` 是测试桩填入的单位数，不能当成真实 token 或费用。

## 用户执行的真实模型验收

先运行单家，核对 8 个结果及来源；成功后再运行三家，核对 24 个结果及供应商隔离：

```powershell
python.exe -m backend.app.agent_demo --case-dir examples/dev-pack-001 --provider configured --mode thorough --question "请完整审查供应商 A 的八项指标，并列出每项结果与来源" --output data/m2-agent-demo
python.exe -m backend.app.agent_demo --case-dir examples/dev-pack-003 --provider configured --mode thorough --question "请完整审查全部供应商的八项指标，并列出每家每项结果与来源" --output data/m2-agent-demo
```

两条命令会向已配置的 DeepSeek 服务发送问题、工具定义以及 Agent 读取的**合成资料文字片段**，可能产生多次计费请求；不发送 `.env`、API key 或原始 PDF/XLSX 二进制文件。`thorough` 仍受 12 次决策、24 次工具、32 次模型调用、累计输入/输出预算和 120 秒期限约束。返回 `partial`、`failed` 或 `waiting_user` 时保留 JSON 记录，先按失败码定位原因，不连续盲重试。请只反馈终端状态、八项/24 项结果、调用数及脱敏错误码，不发送密钥或完整请求日志。真实模型完整审查成功前，M2 只能记为“离线实现完成，真实模型验收待做”。

## 首次真实单家探针与修复

用户首次运行单家 `thorough` 命令，返回 `failed / invalid_tool_result`，模型调用 3 次，记录为 `data/m2-agent-demo/0a4ec469142b426cb02bcbfa1a208ed1.json`。记录显示 Agent 进入 `extract_facts`，两次抽取模型调用完成，工具在校验阶段失败；旧记录不保存候选事实参数，因此不能据此断定模型具体输出。

本地使用原始模拟包复现了一条相符的失败路径：报价表 A6 为“已装内存”，相邻 B6 为自带标签的“已装内存 16 GB”；当模型同时引用 A6/B6 时，旧校验器将其拒为 `fact_field`。现允许这一严格匹配的相邻两格引用，同时保留 B6 单格已足够时的完整覆盖判断；真实 Agent 脚本回归通过。工具失败事件增加固定类别 `failure_detail`，不记录原文或模型参数，便于复测时进一步定位。修复后尚未调用真实模型，需用户只重跑单家探针一次；若再次失败，先查看该工具事件的 `failure_detail` 再决定下一步。

## 第二次真实单家探针与输出预算修复

用户复测返回 `failed / invalid_output`，模型调用 6 次，记录为 `data/m2-agent-demo/c34aad4700324f94a9c9c9fd5da91890.json`。Agent 完成三批内存事实抽取后，在首次七字段批量抽取的模型响应处失败；旧记录没有保存响应的截断标记或原文，不能断言唯一原因。原实现对所有模型调用都只给 512 个输出 token。本地同一模拟包的首批七字段标准结构化结果包含 9 条事实，用 `cl100k_base` 作近似估算为 683 token，因此 512 的上限不足以容纳该批完整结果。

现只将 `FieldCandidates` 抽取上限提高到 1536 token；内存抽取和 Agent 决策仍为 512，`thorough` 的累计输出预算仍为 12000。三供应商离线回归包含未报告 token 用量的保守计账，仍能完成。Provider 遇到 `invalid_output` 时，会在事件中记录经过白名单约束的 `failure_detail`，例如 `output_limit`、`malformed_tool_args`、`missing_tool_call` 或 `tool_schema`；不会记录模型响应或密钥。修复后没有再调用 DeepSeek，下一步只复测单家探针一次，再根据结果决定是否运行三家。
