## 权限、时间与冻结

- 沿用Case优先锁、成员权限、当前版本、attempt/fence、取消和删除守卫。消息、所属对话、来源Run及快照都须属于同一Case。
- 按消息存储时间排序；同一存储时间优先使用首个queued的精确提交时间，其后按对话时间/ID、消息序号/ID及Run ID确定性排序。对话序号与现有API的对话时间/ID排序一致。显示时间取原消息存储时间；数据库的整秒记录不能证明精确发言时刻，缺精确时间的并列记录只保证确定性。
- 沿用B2精确提交截止时间。旧记录没有该字段时保守处理整秒舍入：来源消息时间加一秒仍不晚于截止才允许；旧当前Run缺精确截止时沿用更保守边界。因此临界秒的旧消息可能无法定位，不猜测其时间先后。
- 第一次使用新工具时，把来源元数据和正文哈希摘要冻结到`conversation_summaries`独立kind `first_task_message_v1`；空结果也冻结。同Run显式重试复用来源，不追入后来消息。没有执行新工具的Run不新增该记录。
- 回读前后核对当前权限与原文、归属、来源时间、截止和指纹；变化则拒绝。读取后取消不能发布原话。manifest不含原文，诊断只记录工具名、状态及已有有限错误分类。
- 不迁移数据库，不新增后台摘要调用，不注入Dynamic正式抽取；正式重试直接沿服务端操作登记执行。

复用现有版本化表和守卫，是为避免为这一条查询增加独立存储机制；新增kind与旧摘录、语义摘要、任务交接分开读取，版本号仍在Case锁内分配。
