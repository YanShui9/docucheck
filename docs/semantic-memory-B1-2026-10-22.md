# B1 同对话滚动语义摘要与原消息回读

日期：2026-10-22；实施基线481a531；隔离分支codex/context-request-diagnostics。此记录只代表本地源码与离线验证，尚未合并到主工作区或应用运行服务。

## 本步结果

聊天助手在保留最近8轮完整问答的基础上，把较早讨论整理为目标、已决定事项、未决问题和下一步。每条摘要保留原消息位置，仍可调用现有read_conversation_history读取完整原话。原对话不删除，摘要不确认采购规则，也不是报价或正式审查结论的证据。

只覆盖同Case、同conversation、同资料snapshot及同清单/品目绑定。跨对话任务概况、跨资料版本交接为B2；上下文用量前端入口为C，仍需先确认交互与样式。本步未改前端、没有迁移、没有新增个人事实记忆。

## 使用时会发生什么

例如，一段苹果采购对话持续很多轮：最近8轮仍按完整原话提供给助手，更早讨论可整理为“正在核实税费口径”“下一步执行正式审查”等简短记录。追问旧讨论的细节时，助手仍能按消息位置读取原话。摘要里的“曾讨论每箱25元”不能覆盖已确认清单；采购上限从确认清单读取，供应商报价从原文读取。

当前只覆盖这一个对话及其固定业务范围，不能据此承诺新建对话或切换资料版本后已自动继承全部记忆，也不能称所有超限都已解决。

## 触发与失败处理

- 最近8轮优先保留；更早的完整终态phase按版本正序、每次最多4个新增phase。已有摘要引用的完整phase一并重验；同一消息不同回答阶段使用task_memory_id/phase_digest区分。
- 未整理旧phase达到4个，或实际路由估算达到有效输入75%/已裁减近期原话时，可尝试一次。当前字节估算不是精确token，百分数不作为精确模型窗口用量展示。
- 生成前检查完整摘要消息、完整旧问答、工具schema和输出预留；放不下不截断原话，跳过可选摘要。固定内容及近期原话本身超过50%目标时也跳过，不为摘要消耗模型调用。
- 模型最多返回8条notes，每条最多300字符、1至2个授权原消息位置，整体JSON最多3500字节。结构/引用检查不保证语义总结没有错误。
- 新摘要必须比旧notes加完整来源正文短，且实际路由不超过有效输入50%。首次创建或旧路由超过50%时，还须严格缩小实际路由；已有摘要且空间充足时允许等长或有界增长的内容更新，避免水位停滞。不会为整理而额外丢掉近期原话。检查失败或已知模型错误均保留上一有效摘要，继续原流程。部分旧内容可能暂时仍需回读。
- 摘要与后续路由/正式流程共用一个Budget，生成前为至少一次主回答预留调用、输入及输出空间；已有调用、耗时、显式累计配额、取消保护继续有效。
- 模型前在服务端保存semantic_summary_started标记，同Run显式retry不自动再发摘要。结果未知时保留未知用量、停止本次处理，不能当作零消耗或自动重试。普通日期直答和可信正式重试跳过摘要。

## 持久化与范围守卫

复用conversation_summaries，新增semantic_memory_v1类型；旧source_excerpts_v1单独读写，两类共享conversation全局递增version。历史记录不改写。摘要保存原phase指纹、覆盖水位、范围摘要和内容摘要。

prepare、begin_attempt、save和validate均检查当前Case/Run、成员权限、snapshot、清单、品目绑定、attempt/fence与取消/删除状态。保存使用前一语义摘要ID作CAS；未来head不能成为旧worker的输入，也不能被旧worker覆盖。保存后允许验证自身新head，同时重验原parent和本轮全部来源，防止被省略的来源变化后仍通过。

本仓储仅MySQL连接使用局部READ COMMITTED事务，配合Case优先锁和CAS，避免guard首次普通读在RR下建立旧快照。SQLite验证实际逻辑；隔离级别适配仅做模拟调用合同测试，未进行真实InnoDB并发验收。

摘要不传入正式Dynamic流程，不改变原文、规则、正式覆盖与确定性核验。原消息回读仍受原有范围、权限与版本守卫。context_manifest和模型诊断只保存ID、计数、版本、指纹与有限状态，不保存摘要正文或原对话内容。
