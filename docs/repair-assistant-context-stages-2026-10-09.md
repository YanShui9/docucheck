# 采购助手分阶段上下文修复

> **已应用本机服务：** 代码 `bf8d23d`，API 与四个后台服务已更新；脱敏[应用证据](repair-assistant-context-stages-2026-10-09-applied-evidence.json)。真实 DeepSeek 对话未代用户执行。

## 根因与修复范围

真实“10项候选后追加交期”请求在调用模型前失败。原请求的保守输入上界为 **16014**，单次上限 **16000**；两个 attempt 均为 **0 次模型调用**。历史、摘要、偏好已经全部移除，仍然超限。这里是应用按 UTF-8 字节计算的保守上界，不是 DeepSeek 返回的实际 token 用量，也不是服务商上下文窗口不足。

上一步删除可选记忆解决了较小清单的请求，未解决完整清单及修改工具 schema 随每轮请求一起发送的结构性开销。本步按[实施计划](superpowers/plans/2026-10-09-assistant-context-stages.md)修复这一问题。

## 实现

1. **服务端完整状态与模型视图分离。** 完整候选、来源、条件、原 ID 保存在既有 SQL 绑定中。模型视图去掉来源冗余，但实际候选合并继续使用完整权威对象。
2. **动态工具。** 首次请求提供聊天、检索、目录读取及轻量 prepare_changes；修改阶段才加载严格 ChecklistPatch schema，并仅允许 propose_changes/chat。普通聊天仍一次调用，修改通常两次；读取目录会额外消耗调用。所有阶段共用原调用、输入、输出和时间预算。
3. **受控编辑。** 准备最多四个修改/删除目标，服务端返回这些目标的完整字段；更新/删除其他目标即使 ID 合法也拒绝。新增、更新、删除继续通过原 apply_changes 和 validate_definition；未修改指标完全保留。候选不会自动保存或确认。
4. **有限目录。** 完整基准无法放入请求时，用显式 complete=false 的目录视图。每页最多八项，必要时按剩余预算缩小到四、二、一项，提供实际 next_offset。scope=items 可独立枚举没有指标的品目。新目录页替换旧页，不无限累加工具观察。
5. **复杂单项保护。** 目标完整字段与修改 schema 本身超限时返回 waiting_user/checklist_edit_scope_budget，提示减少本批目标或在清单编辑面板编辑。原清单保留，不截断采购条件。
6. **可信日期。** 每轮组装当前服务器时钟对应的北京时间及 Asia/Shanghai 时区，普通聊天可以据此回答日期；不依赖历史聊天里的日期，不增加查时间的模型或网络调用。
7. **审计。** 记录路由、编辑、证据阶段的请求次数、schema 字节数、最大输入上界与目录读取次数。该审计只含数字/布尔值，不复制采购正文。

采用了[LangChain 官方上下文工程文档](https://docs.langchain.com/oss/python/langchain/context-engineering)中将临时模型上下文与持久状态分离、按阶段选择工具的原则，沿用现有框架和依赖。

- 使用每个现有运行镜像为基础，离线 COPY 应用代码，不下载镜像、不安装依赖；worker/indexer/dispatcher+cleaner 三个镜像的安装包数量分别为 82/82/77，包清单一致。
- 应用前确认 queued/running、待派发、当前版本解析、索引中、Redis runs 队列均为零；停止 API 写入口及 dispatcher，确认 worker active/reserved/scheduled 为零，再更新四后台。未改 MySQL、Milvus、Redis、Keycloak 数据卷与服务。
- 四个容器各 121 份源码，共 **484 个哈希匹配**。环境、只读 CA 挂载、用户、网络不变；其他 **14 个容器未重启**。
- API 用原 OIDC 参数从当前 Conda 环境重启，进程 20940；live/ready 与前端 15173 均 200，API 及前端代理未登录均 401，OIDC 元数据 200。前端进程未重启，页面样式未改。
- 两个 waiting_user 的 Run/attempt/fence 保持；五条 ready 索引、派发与解析状态保持。真实十项任务的 heads、保存/确认操作、Run 行及 assistant 绑定/候选完整指纹前后一致。
- **实际 worker 只读回放**使用真实 MySQL 绑定、历史和摘要，加脚本化 Provider，输入上界 **14039 / 15885**。原十项逐字段保留，生成十一项内存候选；模型 API、Embedding、真实业务写入均为 0。两份回放的工具调用 ID 不同，输入上界以各自实测结果记录。

本步未执行真实 DeepSeek 对话或浏览器内新增、保存按钮验收；HTTP、前端自动测试和脚本化回放各自覆盖的范围如上，不能合并解释为已完成在线模型端到端验收。

原镜像标签保留为各服务的 `pre-assistant-stages-20261009`，对应上一步已支持候选绑定封套的版本。回退时仍须经过闲置门禁、整体恢复对应源码/API 与后台，并重新核对配置和业务状态；不能只回退一个进程或跳过绑定格式兼容检查。

## 保留边界

- 清单领域上限仍为 100 项、20 个品目；准备批次最多四个已有指标及四个品目。
- 不承诺无限对话、无限资料或任意长度单项都能进入一次请求。极端内容仍受原安全预算约束。
- 检索后仅可继续检索或选择已回读原文；正式审查仍必须使用明确确认的版本。现有候选链、来源、取消和版本保护继续有效。
- 日期来源是宿主时钟；错误的宿主时间需在宿主修正。
- 本步不改页面样式、不替用户重试真实任务、不自动修改真实候选或确认清单。
