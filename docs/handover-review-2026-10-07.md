## P1：优先修复

### R01 编辑后的指标可能按旧规则确认（新增）

位置：`frontend/src/components/ChecklistPanel.vue:247`、`:514`、`:227`；`backend/app/db/checklist_repository.py:478`。

已保存“数量至少 20 箱”，将本地指标编辑为“至少 200 箱”，点击编辑表单的“保存修改”，然后直接确认。实际 PUT 次数为 0，POST 仅传指标 ID 和版本，后端按已保存草稿确认，界面却仍可显示 200。

风险：用户看到的规则与正式执行规则不同。已有草稿时打开同 ID 的未保存候选也有同类风险。

修复：跟踪本地未保存修改；候选或编辑未成功保存前禁用确认。确认绑定已保存定义及版本，成功后使用服务端 confirmed definition 更新显示。增加“20 → 200 未保存不得确认”和“已保存后才按 200 确认”的契约测试。

### R02 部分确认后保存剩余项会移除已确认项（新增）

位置：`ChecklistPanel.vue:132`、`:208`、`:230`；`checklist_repository.py:469`、`:490`。

草稿 A+B，先只确认 A。服务端返回 confirmed=A、剩余 draft=B；前端仅展示 B。继续“保存草稿 → 确认 B”，PUT 的替换语义清空累积 base，最终正式版本只有 B。隔离数据库实测：`rice-0` 已确认后最终版本仅剩 `rice-1`。

风险：正常操作无明确删除提示却移除已确认的采购约束。

修复：明确展示已确认与待确认项，保存时提交用户看到的完整清单，或提供保留 base 的专用草稿编辑协议。任何正式指标移除都应在确认前展示。不要直接改变后端已有明确替换语义而破坏既有版本测试。

### R03 旧清单的异步响应覆盖新资料版本（新增）

位置：`ChecklistPanel.vue:158`、`:197`、`:221`；读取的 scope 守卫在 `:121`，mutation 未沿用。

在 s1 苹果清单发起保存并暂缓响应，切到 s2 橙子清单且读取成功，再返回 s1 响应：当前 props 仍为 s2，但画面被覆盖为苹果及资料版本 v1。

风险：误导用户，后续操作可能把过期清单与当前资料版本组合提交。未证明服务端越权。

修复：save/confirm/adopt 发起时捕获作用域，响应、错误、busy 清理与事件发出均校验仍为相同作用域；切换时清理编辑和确认状态。用可控 Promise 覆盖三个 mutation 的迟到响应。

### R04 事实修正成功后仍展示旧正式结果，且第二次修正失败（部分已披露，影响扩大）

位置：`frontend/src/components/ReviewPanel.vue:172`、`:192`；后端 `backend/app/db/dynamic_repository.py:584`。

成功回调只追加本地审计卡，没有刷新 checks/facts 或更新 payload digest。复现显示面板仍为“满足 · 正式”，而 mock 服务端已变为非正式；第二次请求仍携带旧 digest，返回 `run_changed`。后端已有同源冲突测试证实：修正引入备选并置 needs_review 后，该 Run 正式标记会归零。

风险：界面与真实结果/导出不一致，不仅是交接所述“第二次修正不方便”。

修复：成功后在相同 Run 作用域下读取服务端最新 checks/facts/audits/digest；刷新期间不要保留可被误认为当前正式结论的旧标记，并禁用重复提交。检查连续修正和导出一致性。

### R05 以上一版为底稿可能无法保存/重确认（已披露问题的新增阻断影响）

位置：`ChecklistPanel.vue:163`、`:305`；`backend/app/db/document_repository.py:191`；`checklist_repository.py:121`。

底稿直接复制旧 evidence_refs；资料升版后，即使保留相同原文，文档/证据 ID 也会重新生成。隔离数据库复现：将旧 definition 保存到新 snapshot 返回 `checklist_source_scope`。

风险：有原文引用的指标无法通过该入口完成升版确认。交接只披露“查看原文 404”，范围不完整。

修复：复用时重新核对并绑定当前快照证据；无法可靠匹配则要求重新检查，或经明确操作改为用户设置。仅修改打开原文的 snapshotId 不足以解决保存阻断。

### R08 跨 Run 留存旧事实/审计，迟到响应串入新 Run（新增）

位置：`ReviewPanel.vue:136`、`:172`、`:192`；`frontend/src/App.vue:414`。

两个确定复现：切 B 后辅助读取失败仍显示 A 的事实/审计且无提示；A 修正 POST 挂起，切 B 且读取全部成功，再完成 A 的请求，B 的报告下出现 A 审计卡。

修复：切换前清空旧作用域数据；辅助读取失败明确提示；mutation 捕获 Run/输入快照，返回后验证 scope。可使用组件 key 加强隔离，但仍需处理卸载和异步响应。未发现服务端静默跨 Run 写入或越权。

### R09 修正表单无法处理枚举/存在性事实（新增）

位置：`ReviewPanel.vue:159`、`:167`；`backend/app/criteria/facts.py:140`。

表单要求单位非空并把 value 统一当字符串 trim；后端枚举要求单位为空，presence 要求 bool 值且单位为空。枚举留空被前端阻止，填单位被后端拒绝；bool 存在 trim 类型风险。

修复：按规则类型生成修正控件并保持值类型，遵守每类单位约束。添加真实非数值修正契约测试。

### R10 加载更早历史只出现问题，没有对应助手答复（新增）

修复：对更早页面新增 Run 分批读取并校验作用域，复用初始加载逻辑。测试必须检查旧问题和旧答复都恢复，而非只检查消息数量。

### R11 只改变记忆有效期无法保存（新增）
