# 历史原话回读补修

日期：2026-10-23。用户在[真实验收](context-live-service-2026-10-23.md)之后授权优先处理历史链路。本步只修改后端历史读取，不修改前端、正式事实抽取或答案排版。

## 原因与证据边界

原两次真实请求均为history_scope：同任务最早原话回读、新对话回忆上一段最后请求。旧事件没有记录历史工具名或参数，因此无法证明原模型具体选错了哪个工具、哪个消息或分页位置。本次没有把离线重建说成原调用重放。

代码与离线反例确认：read_conversation_history固定本对话与当前资料快照，read_task_history固定本次任务交接的来源白名单；模型即使持有合法交接句柄，交给前者仍会被拒绝。原助手直接结束，缺少纠正机会，失败工具也没有独立诊断。交接来源有界，不能满足任意全任务历史搜索。只读数据库核对确认原对话序号1仍保存“我想买苹果20箱。然后每箱的单价不得超过25块”，没有被删除；维护者核对不等于模型已有相应回读权限。

## 补修行为

- 两个工具说明各自读取范围。只对仓储明确返回history_scope的已知范围拒绝提供一次纠正机会；schema参数错误仍沿用原输出校验。
- 首次拒绝返回与原工具调用ID配对的观察，提示使用已提供的消息句柄及正确工具。恢复阶段只开放已配置的历史工具和聊天，不允许执行历史中的审查或清单修改请求。
- 纠正后仍由原仓储核对权限、归属、快照、冻结白名单和截止时间。没有跨Case、跨版本任意读取或自动换reader旁路。
- 第二次范围错误、重复同一工具及参数立即停止；分页位置变化仍可继续。未成功回读时，模型聊天不能用杜撰原话覆盖失败，服务端提供中文范围说明，不直接显示history_scope。
- 两类工具的成功/失败记录仅保留工具名、状态和有限错误分类，不保存参数、消息ID或正文。取消、版本变化及未知模型响应继续停止，不自动重发。
