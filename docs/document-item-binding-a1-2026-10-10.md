## 实际代码

1. 严格定义整份单品文件、XLSX 行列矩形和 PDF 连续页面三类选择器。服务端把范围展开成原有证据 ID，并独立保存品目锚点。标题不能扩大事实范围，也不能跨行拼接数字原文。
2. 品目名称、供应商 SKU、旧上传产品标识分类分别表示。未知分类留给后续规则保守处理；已知其他品目、明确否定、型号/款号/SKU 冲突拒绝确认。当前只支持明确标注的有限 ASCII SKU，复杂型号不能因此自动视为匹配。
3. MySQL 增加不可变版本、当前 head 和幂等回执表；迁移为 `0017_item_bindings`。动态/助手 Run 增加 nullable 关联身份列，历史 NULL/NULL 保留原意义，目前尚未接入执行器。
4. 增加受项目成员权限保护的当前/历史 GET 和确认 PUT。请求和响应有 Pydantic schema。确认需要资料、清单、关联三种 revision 前置条件、显式确认、理由、操作者和幂等键。queued/running 时拒绝修改；viewer 可读不可写。
5. `freeze_current` 和 `load_frozen` 在同一事务内验证真实 Case、快照及持久清单；空关联也有明确摘要。原清单版本和原文按 hash/parser/证据指纹重验，读取历史不换成最新 head。
6. Case 清理增加三张新表的依赖顺序；迁移降级在已有版本或 Run 身份时拒绝丢弃历史。未自动迁移现有业务数据库。
