# M2-2d：PDF 矢量绘制与注释覆盖检查（2026-09-26）

本步处理正文都已抽取、但 PDF 的可见线框或注释被忽略后仍返回 `complete` 的风险。只改后端解析覆盖校验和离线测试；没有调用模型 API、启动 Docker、安装依赖或修改前端。M2-2 整体仍未验收。

## 第一步：复现误判

测试生成带 `Supplier specification` 正文的 PDF，并分别在页面内容流、实际调用的 Form、嵌套 Form 中画表格线框。模拟 MinerU 中间结果只有正文。修正前这三种页面都被误判为 `complete`。只含文字的 Form 和未被调用的绘图 Form 作为对照，不应仅因资源存在就标记为不完整。

审查又发现：可见 `/Stamp` 注释的外观流也能画线框，但不在页面内容流中。新增带矢量外观的注释，以及无外观流但含内容的文字注释；修正前两者同样被误判为 `complete`。

## 第二步：修正判定

`verify_pdf_source_coverage` 逐页扫描实际执行的 PDF 内容流。遇到描边、填充或着色的绘图操作时，记录 `page:<零基页码>:vector_graphics_unverified`，文件标为 `partial`。`Do` 调用会按当前资源字典递归进入 Form，因此能检查嵌套 Form；未调用的 Form 不参与判定。无法解析的 XObject 或循环调用记录 `xobject_unverified`，不返回虚假的完整结果。

页面存在注释时，按位置记录 `page:<零基页码>:annotation:<零基序号>:unverified`，同样标为 `partial`。即使注释没有显式外观流，阅读器也可能生成可见内容，因此不凭页面正文认定它已覆盖。原有可提取文字与嵌入图片检查继续执行。正式 `parse_pdf` 和模拟包缓存绑定入口共用这个校验。解析版本增加 `/vector-graphics:1/annotations:1`，新快照证据 ID 随版本变化。

## 第三步：离线验证

新增页面直接绘图、Form、嵌套 Form、带外观注释、无外观注释及两个对照场景。测试先证实旧逻辑误判，再验证修正；解析和证据范围定向测试 30 项通过，后端全套测试 **125/125 项通过**，全目录 Ruff 与 `pip check` 通过。本步没有重新运行真实模型对话。

## 边界与下一步

`partial` 表示现有文字证据无法证明矢量图或注释所表达的信息已被抽取，不表示每条线或注释都与采购有关。装饰线、色块、普通链接注释也可能保守地触发 `partial`；本步不尝试把线框自动解释为表格事实，也不为其生成可引用证据。无框文字表格的行列语义、其他未识别 PDF 结构，以及 XLSX 其他不支持结构和任务级限额仍需后续小步处理。下一小步拟检查 XLSX 其他结构；开始前仍按一次一个步骤的方式确认范围。
