# 资料与采购品目对应：A3 范围检索与后端验收

日期：2026-10-10。已完成已确认设计的后端 A3，后端 A1/A2/A3 源码与门禁全部完成；前端 B、真实模型和浏览器闭环 C 尚未执行。业务库仍未应用0017，运行服务仍使用原版本。

## 实际实现

1. 检索器从服务端验证后的 Run 冻结对应中取得允许证据集合。模型只能选择已确认清单的 `item_id`，不能提交范围、任意证据白名单、对应版本或摘要。恢复任务沿用原版本，不读取最新 head。
2. BM25 在建立词法语料、表头和邻近上下文前过滤范围。`read_source` 的显式证据、邻近读取和字符偏移读取采用同一允许集合，范围外标题不自动加入数值来源。
3. dense 使用已有原件 chunk，不修改 Embedding 文本、chunk/schema/fingerprint。只有底层所有证据均在允许范围内的 chunk 才参与检索；其 `chunk_id` 与已有项目/Case/快照/文档/供应商/generation 条件共同进入 Milvus filter。返回须通过本批集合和指纹重验，即使是其他范围的真实指纹也拒绝。
4. 每批最多100个 chunk、总共最多4批、每个过滤表达式最多16,384字节。多批候选按同一 COSINE 分数合并，再与范围内词法排名做 RRF；单批适配器保持旧返回约定。数值非有限或越界分数拒绝。
5. 原件粗 chunk 无法精确表达范围、过滤超预算、索引未就绪和依赖失败时，降级为范围内词法检索，携带具体原因、品目和冻结对应身份。未确认范围返回空结果，不扩大到其他商品；任何检索命中与无命中均保持 `complete_coverage=false`。
6. 对应锚点使用独立的 `read_item_binding` 详情读取路径，一次最多4个证据窗口，不扩大数值读取范围。A1 的授权对应详情 API 继续负责展示对应记录；本步未增加普通聊天中重复注入对应表的行为。
7. 助手首轮选择品目范围后，该轮后续搜索或原文读取即使省略 `item_id` 也保持原范围，切换其他品目拒绝。答复记录携带身份；历史重放重验每个原文窗口与该冻结范围，不能将其他商品原文冒充范围内证据。
8. 持久化检索在网络等待前后校验成员权限、当前 attempt、原件属性、冻结对应与索引 generation。SQL就绪清单与绑定同时生效；查询 Embedding 返回时撤销成员权限，会在向量查询和原文披露之前停止。

## 复审关闭的问题

- 范围降级不能统一说成“语义索引尚不可用”。未确认对应、粗块跨范围和过滤预算分别给出中文解释。
- 不能只验证一次冻结版本后永久信任 SQL。读取前后重新验证冻结内容，篡改 Run 对应摘要拒绝披露。
- 普通授权浏览不能沿用上一轮范围检索的 diagnostics。
- 历史答复不能只验证原文真实，还须验证声称的品目范围和冻结身份。
- 补齐真实 Milvus 两批 SDK 分数解析/排序，以及 SQL ready manifest与冻结范围的组合和网络后撤权回归。

## 保守边界

- **普通授权浏览仍可不指定品目。** 首轮省略 `item_id` 是任务资料浏览，服务器没有用自然语言自动认定采购品目。系统提示要求明确品目问题选择目录ID，但不把提示当作硬权限。正式审查和事实判定继续由 v4 全量范围/来源守卫负责，不能把普通浏览摘录当品目判定。
- 如果 XLSX 的既有向量块复制了范围外表头，即使其中数值行属于本品目，该块也不能用于 dense。此时词法降级属于预期安全行为，不是向量服务故障。
- 超过400块的范围保留有限成本边界，走范围内词法；本步不承诺大范围 dense 召回率或BGE-M3语义准确率提升。
- 范围检索不能证明字段缺失；正式审查仍全量处理适用原文，未关联尾部、解析 partial 和不完整抽取保留 A2 的保守覆盖逻辑。
- 本步 Milvus 实连使用确定性合成向量，验证过滤、分数解析、排序和原索引兼容；没有调用 Ollama/BGE-M3或真实Provider，不能将此结果称为模型端到端验收。
