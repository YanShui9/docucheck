# M3-4 FastAPI 入口：Case、会话、消息和 Run

## 本步实现

本步新增本地 FastAPI 工厂 `backend.app.api.main:create_app`，默认读取项目 `.env` 中的 MySQL 配置。数据库连接由 `backend/app/db/connection.py` 统一供 API 与 Alembic 使用。空 Case 从 revision 0 开始；会话归属该 Case。输入快照由后续上传步骤创建，本步不把空 Case 伪装成已有采购资料。

| 方法与路径 | 当前行为 |
| --- | --- |
| `POST /api/v1/cases` | 创建空 Case，返回 ID 和 revision 0 |
| `POST /api/v1/cases/{case_id}/conversations` | 创建该 Case 的会话 |
| `POST /api/v1/conversations/{conversation_id}/messages` | 带 `Idempotency-Key`、问题、模式和 expected_revision 提交；原子创建消息、Run、Attempt 和 Outbox，返回 202 与 Run 地址 |
| `GET /api/v1/agent-runs/{run_id}` | 返回当前 Run 状态、快照版本、答案字段和 `is_current` |
| `GET /api/v1/agent-runs/{run_id}/events?after_seq=` | 按 seq 升序读取最多 100 条事件，返回下次游标 |
| `POST /api/v1/agent-runs/{run_id}/cancel` | 原子取消仍可取消的 Run |
| `POST /api/v1/agent-runs/{run_id}/retry` | 带 `Idempotency-Key` 与 expected_revision 显式创建新 Attempt |
| `GET /health/live`、`GET /health/ready` | 进程与数据库连接状态 |

验证错误为 422，未知对象为 404；版本、快照、幂等和状态冲突为 409。错误体统一为 `error.code/message/details/request_id`，响应头另带 `X-Request-ID`；校验错误不回显用户问题原文。旧快照 Run 仍可查询，但 `is_current=false`。同键同载荷的消息提交在 Case 版本更新后仍返回原回执；新请求使用旧版本则拒绝。

## 用户本机的真实 MySQL HTTP 验收

在已激活 `docucheck` Conda 环境、项目根目录，且 MySQL 容器保持健康时运行。测试在进程内调用真实 FastAPI 路由，写入并清理随机 ID 的临时 Case/会话/快照/Run；不启动网络服务或调用模型。数据库密码只从本机环境或被 Git 忽略的 `.env` 读取。

```powershell
$env:DOCUCHECK_RUN_MYSQL_TESTS = '1'
python.exe -m pytest backend/tests/test_api_mysql.py -q
Remove-Item Env:DOCUCHECK_RUN_MYSQL_TESTS
```

预期 `1 passed`。若失败，请发送脱敏的 pytest 错误与摘要，不发送 `.env` 或密码。

**实际结果（用户本机，2026-09-28）：** 用户显式启用 MySQL 测试，运行上述 pytest 命令，反馈 `1 passed in 2.50s`，随后清除了 `DOCUCHECK_RUN_MYSQL_TESTS`。这验证了测试覆盖的 MySQL 写入、API 提交重放、Run/事件读取和取消；测试使用进程内 HTTP 客户端，没有启动网络监听服务。

若要单独查看本机 HTTP 健康接口，可在项目根目录启动服务：

```powershell
python.exe -m uvicorn backend.app.api.main:create_app --factory --host 127.0.0.1 --port 8000
```

在另一个 PowerShell 窗口运行 `Invoke-RestMethod http://127.0.0.1:8000/health/live` 和 `Invoke-RestMethod http://127.0.0.1:8000/health/ready`，两者应返回 `status: ok`；结束时在服务窗口按 Ctrl+C。本步的 MySQL HTTP 测试不需要启动这个网络服务。

## 边界与下一步

本步没有文件上传、解析入库、正式核验结果接口、澄清回复接口、用户认证或 Celery 执行接线。空 Case 因没有输入快照，正常请求会得到 `snapshot_not_ready`；测试用隔离数据建立快照以验证提交链路。当前 API 只面向本机单用户开发；实际服务启动须绑定 `127.0.0.1`。M3-4 在上述范围内完成验收；下一小步处理文件上传与快照准备，再接 worker。任何前端代码开始前先讨论设计规范与样式。
