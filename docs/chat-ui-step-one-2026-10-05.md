# 聊天前端第一大步交付

日期：2026-10-05。用户已批准 [中文聊天界面方案](superpowers/specs/2026-10-05-chat-ui-redesign.md)，本轮完成 [三大步计划](superpowers/plans/2026-10-05-chat-ui-implementation.md) 的第一步。

## 已实现

- 白灰背景、低饱和绿色、可折叠采购任务导航；中央聊天和底部上传输入区。资料与旧历史核验按需展开，原文引用仍接已有 EvidencePanel。
- 真实 GET conversations/messages 和 Run/assistant-result；未上传文件可按 revision 0 发普通聊天，首次发送或上传自动建立采购任务。任务创建共用一次正在进行的请求，任务/工作区切换不会被旧响应抢回。
- 历史消息按真实 user message 对应 Run 恢复。澄清后同一 Run 的当前答复只放在最后一条关联用户消息之后，不补造已经被后端覆盖的中间答复。
- Enter 发送、Shift+Enter 换行，保护中文组合输入。草稿按工作区、采购任务及对话在当前组件内隔离；没有把尚未发送文本说成已入库的长期记忆。
- 队列状态轮询、停止、waiting_user 澄清、显式重试；未知 POST 复用原 body 和幂等键。中断且模型结果未知时说明再次调用模型的可能性，不自动重发模型任务。
- 每个 Run 的状态读取都有请求序号。迟到轮询及结果核验响应不能覆盖停止或重试后的新状态；网络轮询失败延迟10秒重新读取，权限失败清理内容并停止展示。
- assistant 来源核验失败不回退未经验证的 answer_text；旧 legacy 历史答复兼容。所有文本使用 Vue 转义插值。只读成员可浏览全部任务，写操作仍受前后端权限约束。
- 上传用途改为需求/订单、供应商报价、产品说明/资质；产品标识选填，沿用现有后端合同；水果等资料无需虚构设备型号。供应商编号及中文名称当前仍明确填写。

## 剩余范围

1. **第二大步**：完整候选清单展示、任意品目/指标手工编辑、保存草稿与明确确认；动态报告、供应商中文名称读取与来源/修正/导出联动。当前候选只展示尚未保存确认的提示，历史核验面板仍保留旧八字段功能，不能视为动态报告前端已完成。
2. **第三大步**：有限记忆偏好设置、中文状态细化、覆盖面板焦点与键盘返回、长历史的渐进分页、统一业务与浏览器验收。

本轮历史分页逐页读取，最多20页、每页100条；超过上限明确报错并阻止把未读取历史当空会话提交，不承诺无限历史。任务摘要从实际第一条消息派生，当前刷新后为选中任务重新读取，不等同于持久任务改名。没有伪造 token 流式输出。后端 RAG、长期偏好与动态规则的前端完整交互仍按剩余两步接入。
