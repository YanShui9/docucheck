# 上下文 A2a：模型窗口与累计用量分离

开始日期：2026-10-21；完成源码及离线验收：2026-10-22。源码基线 `efab4a5`，实施位于本地隔离分支 `codex/context-request-diagnostics`。本记录只描述源码和离线验证，未更新运行服务，未推送或调用真实模型。

## 问题与变化

原先 standard/thorough 分别固定限制单次输入估算 16,000/24,000、累计输入 48,000/96,000 和累计输出 6,000/12,000。这些应用额度可能先于模型容量结束处理。A1 已补齐拒绝诊断，本步将模型窗口和任务累计额度分开。

- 三条入口（聊天、动态审查、旧兼容图）统一由 `Budget.for_provider` 读取当前模型窗口和可选配额。
- 模式只决定决策、工具、模型调用次数。默认累计输入/输出只统计，不再带上述固定硬限。
- 本次输入空间 = 配置模型窗口 − 本次输出预留 − 窗口安全余量，默认余量5%，向上取整。显式注入更小 `max_prompt` 时仍尊重该限制。
- 每次输出上限、调用次数、工具次数、120秒执行期限、单次超时和取消继续约束执行。未知结果不自动重发；没有usage仍显示未知，保留预留。
- 明确配置累计硬限时，调用前保守预留、收到实际usage后校正；达到上限分别记录 `input_budget` / `output_budget`，正文给出中文说明。旧 `token_budget` 历史诊断仍可读取。
- 所有历史选择/裁减使用同一有效输入空间，保留当前完整问题、规则和工具调用配对；没有自行生成摘要或删掉业务记录。

## 估算口径及容量边界

本步没有已核实与当前 DeepSeek V4.1-Flash/兼容接口匹配的本地分词器，不用其他模型的分词器冒充精确计量。继续采用 A1 的消息字段投影和工具定义 UTF-8 序列化字节数加512，诊断明确标为 `utf8_bytes`、`exact_tokens=false`。

准入采取保守策略：每个配置token只允许一个估算字节。比如窗口配置1,000,000、本次输出4096、安全余量50,000时，输入最多945,904个**估算字节**。这不是945,904个实测token，也不能证明服务商接受真实1M输入；A1估算不等于SDK最终网络载荷。由于兼容接口可能有额外封装，不将本策略称为数学上保证不超限的精确上界，不生成精确占用百分比。

实际消耗仍以接口返回usage为准；`input_reserved` 沿用既有协议，表示已知usage与尚未知请求的保守预留合计，不能作为精确累计token或当前窗口占用展示。DeepSeek 官方也要求以模型返回usage确认实际用量，分词方式随模型而异，见[官方说明](https://api-docs.deepseek.com/quick_start/token_usage/)。

这一步解除旧的固定额度，匹配分词、完整请求估算改进、工具结果/资料缩批及恢复继续在A2b落实。本步不宣称整个A2或历史自动压缩已经完成。

## 配置与兼容

| 配置 | 含义 |
| --- | --- |
| `DOCUCHECK_MODEL_CONTEXT_WINDOW` | 现有必填模型窗口容量，不能从模型别名猜测接口支持范围 |
| `DOCUCHECK_MODEL_CONTEXT_SAFETY_PERCENT` | 新增可选整数，默认5，允许0–99；输出另外预留 |
| `DOCUCHECK_RUN_MAX_INPUT_TOKENS` | 新增可选累计输入硬限，未设置或空白表示不设硬限 |
| `DOCUCHECK_RUN_MAX_OUTPUT_TOKENS` | 新增可选累计输出硬限，未设置或空白表示不设硬限 |

累计限额设置时必须为1至2,147,483,647的整数；无效配置只返回安全错误码。空白可用于Compose的可选透传，0不代表无限。更新配置示例及Compose变量传递，没有读取或修改真实 `.env`，未启动容器或解析带真实环境展开的Compose配置。

A1诊断版本继续兼容。增加估算单位、准入方法、安全余量及显式配额；无硬限用null，旧记录缺少这些字段仍可读。诊断沿用有限白名单，不保存资料原文、问题、工具参数或凭据。正式审查规则、来源/权限/快照校验、缓存和事务协议没有变更，不需要数据库迁移。
