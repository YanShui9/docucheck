# B1 同对话滚动语义摘要

基线：481a531；日期：2026-10-22。执行已批准上下文设计的B阶段第一个独立步骤。只在现有隔离工作区实现后端、本地提交，不合并/部署/推送，不改前端或真实.env，不调用真实模型。

## 范围与设计

同Case、conversation、snapshot和当前清单绑定维护结构化辅助摘要。最近8轮原话继续保留；较早完整终态phase按版本正序、每次最多4轮纳入一次滚动摘要。已有摘要引用的原phase与新phase一并授权校验，旧消息可用现有read_conversation_history回读。

在较早未整理phase达到4轮，或实际路由上下文估算达到有效输入75%/已裁减近期原话时尝试；每个Run最多一次摘要模型调用，目标为输入50%以下，若固定内容自身超过目标则保守回退。比例仅按既有标明单位的保守字节估算使用，不显示精确token比例。摘要输入/输出及schema必须先准入，不截断某轮原话；放不下则不发摘要请求。

输出最多8条notes，每条kind为goal/decision/open_question/next_step，text最多300字符，每条最多2个source_message_ids；整体JSON最多3500 UTF8字节。来源只能是服务端给定完整历史phase，模型不能设置权限、范围、版本或完成状态；来源引用校验不等于证明语义总结零幻觉。禁止将摘要作事实证据或已确认采购规则。

复用conversation_summaries表，新增kind=semantic_memory_v1；旧source_excerpts_v1读写继续隔离且共享全局递增version，不改历史行，不新增迁移。摘要记录包含来源phase指纹、已覆盖版本水位、绑定摘要和内容摘要。读取重验来源，写入持Case/Run权限、snapshot/checklist、attempt/fence守卫；CAS前一摘要ID，旧worker不得覆盖新状态。

显式retry不自动复发同Run已登记过的摘要尝试：在模型前写有限服务端审计标记；未知结果必须显示未完成并保留用量，不自动重发摘要。已知错误/输出不合法或无实际缩减时保留上一有效摘要，继续原有近期窗口与回读。摘要与后续路由/正式流程共用同一个Budget。原始聊天不删除。

实际缩减按两种情形验证：第一次创建摘要或旧路由超过50%目标时，候选必须使实际路由严格变小且降至50%以内。已存在有效摘要且旧路由本就在50%以内时，允许同长度或有界增长的滚动内容更新；仍须比旧notes加完整新旧来源正文短、整体≤3500字节且新路由≤50%，不额外丢近期原话。避免要求摘要无限变短导致水位无法推进。

本步只接聊天Assistant入口；直接Dynamic/旧八字段入口维持原行为。跨对话任务概况和跨资料版本交接为B2独立步骤。
