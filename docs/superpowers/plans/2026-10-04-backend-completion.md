## 范围与契约

1. 接收 `ollama-milvus-live-2026-10-04.md`，修复报告中的“硬盘”词法召回反例；保留原始失败及本轮回归。向量近邻不证明有答案，也不能替代完整核验。
2. 补齐 B 的自然语言要求变更候选：基于当前草稿或确认清单，保留未修改指标的稳定 ID；由程序产生差异摘要，变更来源为用户设定，原文要求与用户更改不得混淆。只返回候选，用户通过现有草稿/确认 API 明确生效。
3. 增加普通中文聊天与资料问答入口，按现有 Run/队列/权限/预算/记忆生命周期执行。模型通过受控工具选择回复、检索、提出变更或审查；资料答复校验引用与原句，无法找到直接来源时明示本次检索未找到，不输出完整核验证据不足。正式审查仍走确认版本和全量覆盖路径。
4. 新建任务还未上传资料时允许普通聊天；空范围不得注入其他任务资料。已有任务的问答使用 SQL 授权及持久索引的混合检索，索引未就绪时明确降级。新增接口保留原消息默认 review 行为，未来聊天页使用新 assistant 操作。
5. 多品类、多品目、清单增删改、部分确认、无答案及干扰材料统一回归；复跑旧八字段兼容、迁移/依赖/静态检查和全部离线测试，再做必要小规模真实 MySQL 与 BGE/Milvus/聊天模型联调。

## 实现约束

- 复用现有生命周期，不将普通聊天同步阻塞在 HTTP 请求里；所有结果和已知用量有持久记录。
- 新规则采用有限 schema，不执行模型代码；模型不能代用户确认、更改身份或跨范围读取。
- 所有变更候选绑定资料、基准清单与修订号，确认前重新校验；取消/失效阻止最终提交。
- 空资料是明确的空快照，不能用假文件冒充解析证据。保留旧非空 loader 的默认约束；迁移允许 revision 0 的空快照仅用于新聊天入口。
- 普通聊天回复不作为采购事实；文档问答返回经原文核对的摘录及定位，模型判断相关性仍有质量限制。
- 正式审查共享一次 Run 的预算，不因路由或子流程而重置调用上限；回答、规则和导出按现有版本绑定校验。
