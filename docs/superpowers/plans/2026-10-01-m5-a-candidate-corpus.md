# M5-A 候选语料准备

用户已授权：先找 GitHub/社区材料，无法凑成完整资料集时自行补充。此计划仅完成 M5-A 的准备与校验，不进入 M5-B。

## 判断与范围

已检查五个 GitHub 仓库的递归文件目录，以及 BidCorpus、ProcureTap、CompanyDocuments 数据卡。找到类似项目、招标文本和问答；本轮没有找到可直接复用的中文笔记本八字段配套验收集。记录日期、仓库提交与限制，不按星数宣称可靠，也不执行外部代码。现有七份公开原件继续作为真实文档结构/上传边界子集，不能拼成虚假的真实成交包。

准备 12 个全新、明确标为合成的候选包：6 个校准候选、6 个待独立复核的留出候选；一个校准包有两个供应商，共 13 个供应商、104 格。五文件性能场景在运行前固定为该双供应商包。两个版式家族不跨分组，但作者已见过所有生成资料；因此留出候选不能直接宣称从未见过的独立封存集。必须由用户独立复核，记录污染历史后决定接受、替换或重新提供未见资料。

## 文件职责

- `evals/acceptance/candidate_blueprints.py`：新的原文设计，含不同阈值、型号、缺失、冲突、单位和口径；不含期望状态。
- `evals/acceptance/candidate_gold.json`：人工编写的拟定状态、理由和必要来源角色；不调用产品规则来生成答案。
- `evals/candidate_corpus.py`：确定性生成 PDF/XLSX、独立输入清单与 gold；校验原件哈希、原文定位、供应商、八字段覆盖、缺失范围、家族划分和已有开发集重复；生成待填写的人工复核表。默认离线，不读取 `.env`，不调用 Agent 或模型。
- `backend/tests/test_candidate_corpus.py`：覆盖资产/标签篡改、定位及范围错误、答案泄漏、重复与划分、生成重现性。
- `docs/m5-a-candidate-corpus-2026-10-01.md`：来源结论、候选数量、覆盖矩阵、运行结果、人工复核与封存步骤。

原件位于 `data/m5-candidates/inputs/<pack-id>/`；答案、定位索引和复核表位于相邻 `gold/`、`review/`。输入清单不含 gold 路径或标签。生成到全新目录；已有目录不覆盖，复核后的文件不由生成器原地更新。记录设计哈希、字体哈希、依赖版本，跨环境字节差异需重新核验。

## 本步完成条件

1. 测试先失败再实现；12 包/104 格完整，均在上传边界内，原文定位通过。
2. 同环境重建的原件和 gold 哈希一致；实际上传预检及 XLSX 解析通过。
3. 渲染全部 PDF 页面并检查文字、分页和截断，抽查 XLSX 表格。
4. 定向/后端回归、Ruff、依赖与差异检查通过；记录外部集成未运行项。
5. 交付可操作的人工复核清单。未经独立复核：reviewed=0、sealed=0、业务质量/模型费用/真实时延未测量。不得自动补签或封存。

## 封存约束

复核每格原文、型号、比较口径及必要来源；缺失必须遍历该供应商完整 quote/spec。修正 gold 后重新校验。真实复核人记录日期、每格结论、输入清单和 gold 的 SHA-256、代码基线及使用历史，并确认至少六包不再参与调参。任何输入、标签或分组变更使旧确认失效；若已根据留出结果改规则，该批只能转为校准，需补新留出资料。哈希证明文件一致性，不证明标注正确或人真的独立。
