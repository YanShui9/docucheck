# M3-6 上传文档解析与证据入库计划

> 用户确认继续 M3 下一小步。只实现已上传文档的解析、证据持久化与按快照读取；Celery 调度、Run 执行和前端仍在后续步骤。

**目标：** 让 `pending` 的文档原件生成有页码/单元格位置、可按 Case/快照校验归属的证据块，供后续 Agent worker 使用。

**架构：** `DocumentIngestion` 根据数据库生成的 `storage_key` 读取文件，验证路径留在配置数据根、大小与源 SHA-256，再调用现有 `parse_pdf`/`parse_xlsx`。解析在数据库事务之外执行；文档状态、解析版本、覆盖信息和全部证据块在同一 `Engine.begin()` 事务内条件提交。重复处理已完成文档直接返回原结果。解析失败记为文件处理失败，不生成业务结论。

**入口：** 增加本机 CLI 按 Case/快照处理文档，供人工验收与未来 worker 调用；增加只读 API 查询文档证据和单条证据，服务端校验 Case、快照、文档归属并限制返回数量。PDF 使用本机显式配置的 MinerU 可执行文件；XLSX 无额外依赖。
