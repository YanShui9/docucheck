# M5-A 复核与封存校验

用户继续推进现有M5-A方案。本步补齐已规划的独立人工复核流程，不进入M5-B、不调用真实模型、不启动Docker/前端。

## 设计

现有原件和gold校验已备妥，但复核表和确认模板不能被程序验证，候选校验的reviewed/sealed始终为0。补一个独立的 `evals.corpus_review`，保留 `candidate_corpus` 为纯资产检查，避免将机器检查升级为人类复核。

1. `--prepare`：先校验候选，再向全新复核目录写版本快照、待填CSV和确认JSON。每格加入reviewed_status，默认空，姓名/日期空。记录corpus/gold/输入哈希、当前backend/evals源文件哈希作为代码基线。只读取明确源文件，不读取.env；不生成PDF或改原件。
2. 默认检查：要求每格唯一、对应原供应商/字段，accepted与拟定状态一致、changed需重新修订gold，reviewed_status等于当前gold、复核人/日期与确认一致。未填项报告pending；已填写的无效项报错。确认要求真实人独立复核声明、承认作者已见这批合成资料、无调参声明，以及明确六包留出清单。声明不是身份认证，程序无法证明人真的独立。
3. 显式 `--freeze`：完整资产检查及104格复核、至少六包留出声明满足后，独占创建freeze记录，不覆盖现有记录。当前用户未提交复核，本轮只测试临时虚构复核记录，绝不冻结实际资料。
4. `--seal` 检查：重核资产、原文定位、CSV/确认/快照/corpus哈希，任何变更使旧记录失效。封存记录是本机可核验的冻结声明，不是数字签名或防恶意篡改认证。代码基线记录冻结时版本；后续测量另记执行代码版本，不能因后续新增评测代码而伪称资料改变。

有gold修改时，必须修正标签及必要来源、更新已确认清单版本、重新准备复核；不能自动跟随新哈希接受旧声明。仅回复“继续”不填充复核记录。

## 验证

先观察缺实现失败；测试未复核拒绝、缺格/重复/额外格、错误状态/日期/复核人、changed未修订、版本变化、封存篡改和拒绝覆盖；真实冻结仅在临时测试目录使用明确虚构身份。审查现有清单的错误输入处理，补结构错误测试。最终定向、后端回归、Ruff、依赖和实际待填资料检查；未达人工条件明确保留。

参考：[LangSmith数据集管理](https://docs.langchain.com/langsmith/manage-datasets)中的数据版本管理与 [评测类型](https://docs.langchain.com/langsmith/evaluation-types)中的离线评测/人工复核分工。本步采用本地文件，无新托管服务或依赖。
