# 开发流程优化实施计划

执行方式：使用 writing-plans 与 verification-before-completion，当前会话顺序执行。用户已授权三个大步骤一起完成，不新增逐小步确认。

**目标：** 保存原版本，交付简洁入口、统一离线验证入口、风险审查与度量协议。

**架构：** 标准库脚本复用既有验证器；现有应用、CI 全量门禁与服务部署不变。

**技术栈：** Python 3.12、pytest、Ruff、Git、Markdown；前端沿用 npm/Vitest/TypeScript。

## A：备份和文档入口

- [x] 创建标签、bundle、SHA-256 清单，克隆验证原提交。
- [x] 归档 CLAUDE、路线图、旧小步计划，修正相对链接；更新当前入口、导航和协作协议。
- [x] 比较原文内容、链接及入口字节，检查 diff，单独提交。

## B：统一验证 CLI

- [x] 阅读现有 verify_offline、测试/前端入口；先写运行边界回归并观察失败。
- [x] 实现 `doctor`、`plan`、`check`，复用全量门禁；定向测试必须显式选择，报告区分覆盖范围。
- [x] 测试真实子进程失败、报告冲突、超时、网络隔离及路径限制；通过 Ruff/定向回归后单独提交。

## C：风险审查和度量

- [ ] 交付风险审查模板及 `compare`，比较身份/环境/门禁兼容性，不凭不同测试范围给提效结论。
- [ ] 验证本次归档完整性和文档体积变化，运行新入口的最终全量离线检查。
- [ ] 记录真实结果与未测项，更新导航与计划，验证业务源码未改变，单独提交并推送三个步骤和基线标签。

最终验收：可恢复基线；所有新入口检查可执行；新增工具回归与全量离线验证通过；未新增真实模型/数据库/前端运行；收益报告无虚构 token、业务时延或任务提效。
