# 当前采购任务最早原话补修

用户已确认继续本小步；范围不含前端、正式审查、任意历史搜索或部署。

## 设计与验收

- 新增 `read_first_task_message(start_char=0)`，不接受采购任务、对话或消息ID。服务端从当前 fenced Assistant Run 确定任务及提交截止时间。
- 定位本任务提交本次问题之前的第一条用户消息，可跨对话和资料版本，不依赖旧Run成功或摘要白名单。按原消息存储时间排序，同秒优先精确提交时间，再按对话创建时间/ID、sequence、消息ID确定性排序；缺精确时间的并列记录不能证明真实先后。
- 使用已有Case优先锁、权限、版本、attempt/fence及取消/删除守卫。精确提交时间读取首个queued事件；旧记录仅有整秒时间时采取保守边界，不追入未来消息。
- 第一次使用时把来源（包括空结果）冻结到现有版本化记录；重试不重新选择。原文、归属、截止或来源元数据变化则拒绝。manifest仅含有限来源与摘要，不含正文。
- 工具直接返回服务端渲染的原话和可读对话/北京时间/当时资料版本，结束本轮，避免模型改写。长原话分段，明确总长度与下一段位置，不截断冒充完整；不存在时直接说明本次提交前没有可定位的用户消息。
- 历史原话不能确认当前采购规则、报价或授权执行；不放宽既有两个历史reader。
