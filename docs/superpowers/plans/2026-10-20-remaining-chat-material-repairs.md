# 清单问答、资料关联续用与历史读取补修计划

> 按用户“剩下个问题一同解决了”及后续“继续”的授权执行；沿用已经讨论的交互，不重新请求确认。

**目标：** 清单规则可直接问答，仅规则变更不无故丢失资料对应，历史读取失败不冒充资料为零。

**实现边界：** 已确认版本是问答权威，编辑草稿仍独立；资料对应按不可变版本承接；历史界面沿用现有文字和按钮样式。原文件、旧清单、旧关联和旧Run均保留。

## 1. 已确认清单只读问答

- [x] 先复现没有确认规则读取通道、连续读目录耗尽决策次数的问题。
- [x] 新增有界 `read_checklist` 和阶段限定的 `answer_checklist`，正文短答、来源可读；不触发文件检索、候选修改或正式审查。
- [x] 从Run冻结的清单版本读取完整rule、启停、必选/可选和conditions，禁止用编辑base代替confirmed。
- [x] 答案、版本、完整规则来源联合摘要；历史回读重验并兼容旧记录。
- [x] 回归：25 CNY/箱不含税；草稿999不污染确认25；停用/条件；未读/越界引用；重复目录；大清单定位；持久化篡改与旧协议。

## 2. 仅规则变化时续用资料对应

- [x] 复现规则阈值变化令关联stale。
- [x] 同快照、全部品目ID/名称/规格一致且旧来源重验通过时，确认清单事务创建新的不可变关联版本。
- [x] 已存在stale仅在明确提交新Run时允许承接，GET/历史校验不得写库。
- [x] continuation只指向原人工确认版本，来源验证有界；跨越品目身份变化仍要求重核。
- [x] 正反例、重放/旧摘要、并发与受影响隔离MySQL验证。

## 3. 历史读取失败和竞争

- [x] 先确认永久loading、错误0份、A→B→A覆盖及刷新错误依赖的失败回归。
- [x] 独立loading/error与请求代次，取消旧请求，20秒等待上限；历史刷新直接读所选快照。
- [x] 未读取或失败显示“—份”，成功空结果才“0份”；快照列表给出真实版本，局部中文失败/重试/返回当前。
- [x] 前端全量、类型/构建及真实浏览器合成接口场景验证。
