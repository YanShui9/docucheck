# M3 Backend Closure Implementation Plan

> **For agentic workers:** This plan is executed inline in the current chat. Steps use checkboxes for auditability; no parallel development is required.

**Goal:** Meet the M3 backend completion conditions in `docs/development-roadmap.md` with reproducible MySQL/Redis/Celery evidence and a code review.

**Architecture:** Keep FastAPI as the local entry point, MySQL as the authority for Run/Case state, Redis as Celery transport, and a separate Windows MinerU parser. Use isolated Redis DB 15 and a container-local fake OpenAI endpoint for worker acceptance so no external model request occurs. Reuse the existing source-backed correction and fence contracts.

**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy Core/Alembic, MySQL 8.4, Redis 7.4, Celery 5.6, LangGraph, MinerU, pytest, Ruff.

---

## Scope and exit criteria

M3 is complete only if the following are supported by current code and fresh checks: a session remains readable after process restart; `waiting_user` does not retain a worker slot; duplicate message keys yield one Run/result; an interrupted Run requires explicit retry and rejects the previous attempt; a changed Case revision cannot gain a new formal result from an old Run; an uploaded document becomes source-backed Agent output through the worker; a reviewed correction is consumed by that worker; and a real MinerU invocation can parse the supported sample PDF. M5 quality, cost, and performance targets are separate.
