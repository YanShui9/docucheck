# DocuCheck 最小 Agent 实施计划（M1）

> 执行方式：在当前项目逐项实施，使用 executing-plans 技能检查任务与交付。复选框表示尚未实现；不据此自动启动其他 Agent。

**目标：** 在模拟需求、报价和规格书上，让真实模型驱动 LangGraph 单 Agent 自主调用工具，回答内存核验问题并支持来源追问。

**架构：** 遵守 [Agent 架构 v1.0](../specs/2026-09-24-agent-first-design.md)。M1 在 CLI 内使用快照 repository 和内存执行状态，复用解析输出并补齐版本和覆盖。M3 用 MySQL 实现同一 repository 契约。

**技术：** Conda Python 3.12、LangGraph 1.x、LangChain 模型/工具接口、Pydantic 2、MinerU/openpyxl、pytest。兼容补丁版本在任务 2 验证固定。

## 交付演示

- 第一问：“供应商 A 的内存是否符合采购要求？”真实 LLM 调用工具，读取需求与报价/规格书，得到 16GB 与 32GB 冲突；状态来自规则。
- 第二问：“你根据哪两处判断冲突？”继承供应商和字段语境，返回报价单单元格及规格书页码和原文。
- 故障演示：去掉一份材料的完整覆盖记录，再提同样问题；显示不完整范围，不输出正式满足或证据不足。
- 运行证据保存在被 Git 忽略的 data/，提交脱敏总结；密钥不进入日志。
