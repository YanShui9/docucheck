# M4-D 导出与交付验收执行计划

依据已确认的 [M4 四步方案](../../m4-large-step-plan-2026-09-30.md)和[工作台设计](../specs/2026-09-30-m4-workbench-design.md)。本阶段按三个大块推进，验证时使用本地脚本 Provider；真实模型费用与发送范围另行说明。

## 1. 同源导出

- 为选定 Run 增加受 OIDC/Case 权限保护的 JSON/XLSX 下载。导出从现有 `get_run_checks` 获取同一份来源复核后的结构化结果，保留 Run、Case、快照、版本、运行状态、`is_current` 和每格 `is_formal`。
- 批量补充同快照的证据文件名、页码或工作表单元格、原文；不读取其他 Case 的来源。无结果拒绝下载，历史和部分完成结果显著标记非正式。
- XLSX 的外部文本强制写为文本单元格，不生成公式、链接或宏。测试 JSON 与 `/checks` 一致、XLSX 逐格一致、恶意公式文本仍为纯文本、跨账号返回 404。

## 2. 页面入口和闭环

- 在现有专业审查工作台的选定 Run 区加入 JSON/XLSX 下载，沿用现有登录令牌与错误提示；只有已有结构化格子时允许下载。
- 用确定性本地 Provider 自动覆盖空 Case、上传解析、提问、追问、来源、修正、历史与导出；再在本地 OIDC/MySQL 浏览器检查下载。每次真实模型请求仍由人决定是否执行。

## 3. 交付审查

- 执行后端全量、真实 MySQL 定向、前端测试、类型检查、构建、依赖和静态检查；核对键盘焦点、空/失败态与跨账号权限。
- 写可复现的演示脚本、命令、结果和未覆盖边界，更新 README、CLAUDE 和路线图。M4 只声明本地合成样例范围内验收，M5 保留真实资料质量、费用、性能和生产部署门槛。
