# 资料关联弹窗：状态与操作简化

用户于2026-10-21确认按上一轮分析实施。使用 writing-plans 记录范围，在当前会话连续完成实现、测试、复审和本地提交。

**目标：** 打开弹窗即可分清当前生效的关联、需要重新确认的旧记录，以及本次尚未保存的新增/修改/取消。

**架构：** 保留 Vue、现有 API、服务端版本/证据校验与幂等协议。前端为每行保留不可变的原始关联和编辑结果，保存只提交未取消的编辑结果；其他文件的关联原样保留。

**技术栈：** Vue 3、TypeScript、现有 CSS、Vitest。

## 一、状态与信息层级

- 已关联的文件默认展示当前生效关系，编辑表单按需打开；未关联文件直接进入首次填写。
- 当前生效关系与待保存修改分别展示。修改和取消在保存前不抹去原始关系；每条待变更可撤销。
- 旧关联不适用时显示“需要重新确认”，旧内容只读，不自动复制为新关联。
- 只有当前快照与已确认清单身份匹配时显示当前生效；历史页面明确只读。
- 名称、文件范围、状态优先；确认时间/版本、原文预览、型号和上传信息按需展开。
- SKU 对外称“具体型号或货号”。没有旧上传标识时不显示旧标识分类，保留 unknown 默认值，不自动推断。

## 二、操作与安全边界

- 明确选择商品、真实原文依据、整份文件单商品声明仍为必要条件；不引入模型调用或新依赖。
- 保存前汇总新增/修改/取消数量；尚未发送请求时明确“尚未生效”，未知保存结果单独提示待核实。确认复选框和理由沿用现有协议。
- 取消关联只生成待取消项；撤销恢复原值与原顺序。新增项取消后直接移除，不影响已确认关系。
- 有未保存内容时，关闭和手动刷新先显示应用内提示；继续编辑保留输入，明确放弃后才退出或刷新。
- 未知保存结果不得称为可以撤销的本地修改；提示请求可能已经生效，只重试原幂等请求或读取服务器核对。
- 保存失败保留内容；已收到成功回执但最新读取失败时不再显示旧状态为已确认，不重新发送写请求。
- 不改数据库、历史结论、后端共享 WIP 或登录配置，不上传 GitHub。
