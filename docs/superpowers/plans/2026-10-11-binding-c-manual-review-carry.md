# C 聊天重审保留人工复核

真实手机重审发现 assistant_executor 未传 previous_payload，导致旧人工修正与 needs_review 丢失。DynamicAgent 单独回归通过不能代替执行器联通验证。

1. 使用实际上传/确认/绑定/聊天审查/人工修正/普通聊天/再次审查的 SQLite 业务入口回归，先确认失败。
2. 从数据库读取同 Case、对话、资料快照、清单版本和绑定身份的既有待复核报告；逐份完整验证。保守限制为32份，选最新且要求其事实包含旧报告事实；分叉缺失不猜合并，停止处理。普通模型回答和任务记忆不是修正事实权威。
3. assistant/dynamic 两种执行器均衔接验证报告。沿用 Case 锁、当前权限/attempt/fence 与修正接口 case_busy 边界，运行期间不允许追加修正；不跨资料、清单、绑定或对话带入旧事实。历史存储不改写。
4. 定向及全量门禁、只读复审后本地提交、应用源码，再经浏览器重跑手机与历史变更。保留先前未带入修正的运行作为失败证据，不能称该次重审通过。
