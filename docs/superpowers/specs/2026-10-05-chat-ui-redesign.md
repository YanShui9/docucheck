## 2. 当前页面的问题与技术条件

检查了 `App.vue`、`style.css`、`AgentWorkbench.vue`、`CaseSidebar.vue`、`DocumentsPanel.vue`、`api.ts`。本机5173当前未运行，本轮没有本地网页视觉验收。

- `App.vue` 默认 documents 标签，用户需先找上传与审查入口；空任务不能直接使用新聊天能力。
- 页面存在 Case、快照、八项、型号等实现或设备专用表达，普通采购用户难以对应自己的业务。
- `AgentWorkbench.vue` 固定八项数组、固定“完整审查八项”问题和固定八字段矩阵；`api.ts` 的 FieldKey 尚无动态结果类型。
- 现有全局栏、三栏及表单同时占据页面；普通问答和正式结果没有形成清晰的阅读层级。
- 后端已提供 assistant、动态清单、确认版本、记忆、持久化检索与原文 API，前端需要真正接入。

沿用 **Vue 3 + TypeScript + Vite + 普通 CSS**，保留 OIDC、权限、版本保护、原件查看、历史、取消/重试、事实修正与导出。首版不为视觉引入新的 UI 框架、富文本编辑器或付费组件。

## 3. 三种方向与推荐

| 方向 | 取舍 |
| --- | --- |
| **浅色聊天 + 按需工作面板（推荐）** | ChatGPT/Kimi 的熟悉输入体验，Claude 的对话旁结果查看模式；兼顾普通用户与面试业务演示 |
| 三栏审查工作台 | 可同时看到资料、矩阵、原文，但首页密度大，继续承担用户已指出的理解成本 |
| 深色技术控制台 | 状态与日志醒目，但普通采购用户需要处理更多技术信息，长时间看原文也不方便 |

选择第一种作为具体实施草案。已有“聊天为主”方向保持，以下视觉参数与行为等待用户一次整体定稿。

## 5. 页面和操作流程

### 5.1 首页与导航

顶部只保留产品名、当前采购任务、当前资料状态，以及“资料”“审查清单”“结果”的按需入口。侧栏包括“新建采购”、最近任务、工作区切换，底部为账号/设置；侧栏可折叠。

首页标题：**今天要采购什么？**

说明：**可以先描述需求，也可以上传需求单和供应商资料。**

输入提示：**例如：采购20箱苹果，帮我整理审查要求。**

输入区附三个简短捷径：“描述采购需求”“上传采购资料”“手动设置指标”。不固定食品或设备品类，不预设八项。尚未建立任务时，首次发送或上传再创建真实采购任务和会话；重复点击不得重复创建。

Case 在用户界面称“采购任务”，snapshot 称“资料版本”，Run 称“本次处理”。任务标题首版可使用创建日期和已读取首条消息摘要；没有后端名称字段时不显示无法持久保存的“重命名成功”。如列表需补摘要读取，列为必要的 API 小补充并测试，不用额外模型调用生成标题。

### 5.2 聊天与输入区

- 用户消息使用淡灰底、右对齐；助手答复左对齐，以正文阅读为主，不给每段文字套重边框。
- 首页输入区在中间，开始聊天后固定在对话底部。支持自然增高、附件列表、拖拽上传、发送和停止。
- Enter发送，Shift+Enter换行；中文输入法确认候选字时不能误发送。输入保留与任务/会话绑定，切换任务不把旧草稿发给新任务。
- 用户向上翻历史时不强制滚回底部；出现新消息显示“回到最新”。重新打开会话读取真实持久消息和 Run，不用假聊天填充。
- 初版按既有队列状态、消息/事件轮询反馈，后台没有 token 流时不伪造逐字生成。只能显示已收到的处理状态/阶段，不展示模型内部思维链。
- 运行中显示中文状态、停止操作和失败重试；失败保留问题与附件。标准/全面模式说明处理范围和耗时差别，不冒称开启模型深度思考。

### 5.3 上传资料

点输入区附件按钮打开轻量资料面板。文件选中后明确资料用途：“我的采购需求”“供应商报价”“供应商说明资料”；供应商资料绑定已有供应商或新供应商，以及可选产品/规格标识。不是“所有附件自动同一身份”。

前台显示供应商中文名称。handle 由稳定映射处理；当前读取响应缺少人类名称的地方需要补读字段，不能靠刷新即丢失的临时映射。上传后展示真实上传/解析/索引状态，解析完成与语义检索就绪分别表述。格式按后端实际限制，只承诺 PDF/XLSX。

文件更改明确提示“资料已更新，原审查结果属于旧版本”，并引导新版本清单确认；上传失败、索引失败、权限不足均有中文原因和可执行下一步。

### 5.4 指标候选与确认

助手提出候选后，消息显示“待确认的审查要求”、品目/指标概览和“查看与编辑”。侧面板展示完整动态清单，支持增删改指标与有限规则表单，明确来源是“需求原文”或“用户设置”。

按已有协议明确两个操作：**保存草稿 → 确认审查指标**。保存成功不等于确认成功；第二步显示将生效的品目、指标数和资料版本。未确认/停用项明确标示，部分确认只对选中项生效，旧版本保持可追溯。

确认后消息显示“本次采用 X 个已确认指标”，可以“开始完整审查”。缺少供应商资料时说明需补哪些资料，不把空范围称为审查完成。

### 5.5 结果与原文

普通资料问答显示原文摘录、来源文件和页码/单元格，点击定位打开原文面板，并说明这只是本次检索。

完整审查返回摘要及“查看完整报告”；报告面板按实际已确认指标生成行、供应商生成列，按品目分组，可切换单供应商明细。旧八字段历史独立兼容展示，不把旧报告重新解释为新动态清单。

六类状态：满足、不满足、资料冲突、证据不足、待人工确认、处理未完成。处理未完成不得涂成业务成功；相应结果说明正式/部分及待完成范围。历史结果醒目标记资料版本及“历史结果”。

右侧工作区一次展示清单、报告或原文之一，返回时保留选择和对话滚动位置。大屏可并排，小屏使用覆盖面板；宽矩阵可横向滚动，不挤窄正文。正式结果可下载Excel，审计JSON置于更多菜单。既有原文支持的事实修正保留并显示修正/复核状态。

### 5.6 记忆与权限

账号设置提供现有有限偏好的查看、明确保存、删除与到期说明；不显示未实现的“自动记住所有偏好”。普通历史消息持久化与本轮模型上下文分别解释。

只读成员能看与追溯，不能出现可用的确认/上传/修正按钮。撤权、登录过期、任务删除和资料升版沿用后端校验，前台显示中文状态。危险操作有明确对象与结果提示。

## 6. 实施分三个大步骤

1. **整体骨架与真实聊天**：导航、空任务、输入、消息历史、assistant API、队列状态、附件入口与基础中文文案；保留旧历史/原件路径。完成组件回归、类型检查、构建及浏览器确认。
2. **指标确认、动态报告和资料面板**：接入候选/草稿/确认、真实供应商名称、动态结果和原文联动，补齐必要只读元数据；验证实际采购闭环和旧八字段兼容。
3. **交互完善与统一验收**：响应式、输入法、键盘可达、无结果/失败/取消/升版/撤权、历史滚动与修正/导出；统一审查与实连测试，保留失败记录。

每步都交付可查看结果、测试与规划核对。设计定稿后再写实施计划与代码；不另开几十个确认点。

## 7. 验收标准

- 未上传文件能直接聊天；刷新和重开仍可恢复真实对话，任务切换不串资料、草稿和迟到响应。
- 中文界面主流程不要求理解 Case/Run/快照/内部供应商 ID；输入法确认文字不发送，键盘焦点可见。
- 指标由用户/需求决定；候选须明确保存确认，供应商资料不能自动成为买方要求；未确认项不进入正式结果。
- 问答能打开真实来源；无命中、检索降级、业务证据不足与处理未完成分别表述。
- 大屏聊天/面板比例合理；窄屏可读、输入不被遮挡、表格不把整个页面撑出水平滚动。
- 旧设备报告、登录/权限、版本、停止/重试、事实修正和导出保持可用；界面不展示未实现的按钮或虚构数据。
- 最终运行现有前端测试与新增关键交互回归、vue-tsc/Vite build；浏览器验证空资料聊天与一条动态采购完整闭环，API必要补充也要独立测试。
