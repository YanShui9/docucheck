# DocuCheck Agent 面试展示评测集设计

日期：2026-10-28。状态：用户授权调研，符合主流实践后按方案执行；已完成方法调研并采用下列补强。本文是评测设计，不是完成报告或成绩。

## 目标和完成定义

先交付可以运行、计分、追溯和讲解的 Agent 评测，再开始面向初学者的教学。对象是当前采购助手：正确理解任务、选择受控工具、读取限定资料、完成审查或安全澄清，并保留可信来源及业务状态。

完整交付包括原始 PDF/XLSX、任务及多轮脚本、预先确定的参考答案与必要证据、评分器、离线校验、真实系统运行器、首轮报告、失败分析、复现说明和面试演示入口。评测工具交付与 Agent 质量达标分别判定；低分不会使样本从报告中消失。

本轮不改业务页面，不新增 Agent 架构，不将评测扩成无界产品修复。已有失败保留。发现产品缺陷先记录并给出最小可复现输入；任何影响业务合同的修复另行明确范围，修复后的成绩另起版本。

## 方案选择

| 方案 | 内容 | 取舍 |
| --- | --- | --- |
| 推荐：40 个任务的完整工程评测 | 10 个开发任务、30 个冻结测量任务，附真实轨迹和复测 | 足够覆盖关键能力，规模可审阅，可从失败讲工程判断 |
| 最小演示：8–12 个固定任务 | 复用已有场景整理成演示脚本 | 快，但覆盖不足，容易只证明熟悉样本 |
| 大规模基准：100 个以上任务 | 更多独立资料、多模型、多轮统计 | 需要更多标注、运行和独立复核，本轮无法凭生成数量证明质量 |

采用第一种时，以下数量是先行固定的任务分母，不是预定通过数。

调研结论和逐项对照见[方法调研](../../agent-evaluation-research-2026-10-28.md)。补强要求：任务标注历史失败或需求出处；建立“应执行/不应执行”正反对；每题提供已知可通过评分器的参考 observation；只约束必要工具/参数与安全顺序，不固定无关调用顺序；严格成功率之外公布逐维诊断分；能力测量与历史回归分别报告。

## 任务矩阵

| 类别 | 开发 / 测量 | 主要断言 |
| --- | --- | --- |
| 意图与确认边界 | 2 / 6 | 问答、审查、需求候选、未知供应商澄清；未确认不得改变权威清单 |
| RAG 资料问答 | 3 / 9 | 直接事实、口语改写、PDF/XLSX、长单元格尾部、跨原文组合、无答案、相斥原文 |
| 正式审查 | 3 / 7 | 六种规则、明确不满足、冲突、证据不足、人工确认及不完整覆盖；按供应商/品目/指标逐格计分 |
| 多轮上下文与历史 | 1 / 3 | 指代追问、原问题回读、旧结论不能冒充当前版本事实 |
| 安全与范围 | 1 / 5 | 跨供应商、跨品目、跨用户越权、资料内指令注入、无依据修改 |
| 总计 | 10 / 30 | 40 个不同任务；多轮步骤不拆成多个成功任务 |

RAG 的 12 个任务中固定 8 个有答案、4 个无答案；开发组为 2 个有答案、1 个无答案，测量组为 6 个有答案、3 个无答案。冲突题有答案应表达冲突，不能只报一个数。无答案题必须有明确的可观察安全行为，不用非空检索结果判定幻觉。

正式审查不要求材料声明自动判满足；presence 肯定候选按当前保守合同预定人工确认。不能将已知局限当作未记录的免计分项。

另外单列 6 个工程控制场景：重复提交、幂等键冲突、显式重试保留旧 attempt、排队取消、未知响应不自动重发、向量不可用时的授权范围降级。它们不加入 40 个任务的业务成功率。运行中取消、异机恢复及生产负载不在本轮承诺内。

## 数据和参考答案

使用全新合成采购资料，覆盖手机、水果、服装及办公耗材，至少包含双供应商和混合品目。原有 24 问、18 包及失败报告只作历史回归和选题线索，不混入新测量成绩。

开发和测量以整个采购资料组划分，同一原文、同义问题、多轮会话及仅更换数字的近重复样本不得跨组。新测量资料在调试前冻结，但仍标注 AI 编写、作者已见、独立人工复核 0；不称独立封存集。运行后参与修复的样本标记已用于诊断，不能继续宣称未见测试。

每个任务有稳定 ID、能力标签、输入、前置版本、身份/权限、允许资料、预期行为、禁止行为、参考事实/业务状态、必要证据组、页码或单元格、状态变更断言、评分口径及风险级别。多轮任务另含明确的用户回合与终止条件。

先写需求与供应商原文，按业务合同编写参考答案和理由，再运行产品。不得调用产品规则生成 gold。对争议语义固定保守答案或明确待复核，不能运行后迁就输出。模型只接收正常用户输入和原件，不接收 gold、标签、评分条件或任务 ID 中暗示答案的信息。

生成原件后逐个核对正文、定位、必要证据和哈希；PDF 需检查中文可读性。公开所有合成输入、任务、gold 与可公开报告，凭据及私有业务数据不公开。

## 运行和证据

离线层校验数据合同、来源定位、组间泄漏、计分分母和评分器反例；脚本 Provider 只证明工具行为，单列结果。

真实层使用合法 OIDC 身份与隔离合成工作区，经过实际 HTTP、上传、解析、索引、队列、模型、持久化和导出。配置由测试夹具通过正常接口建立；需求候选能力只在相应任务中计分，不能把夹具预置清单冒充 Agent 生成。越权题使用合法的第二用户验证，不绕过鉴权。不能完成前置身份条件的任务记 blocked，继续占计划分母并单列。

记录应用提交、规则版本、数据和 gold 摘要、模型配置、解析/向量/依赖身份、任务/Run/attempt、允许的工具事件、原文来源、最终答案和状态、错误、延迟、调用/token/未知用量。模型原始结构候选只在现有可合法取得的范围保存；取得不到则明确缺口，不宣称完整内部推理轨迹，也不以事件汇总代替未保存的候选。

先完成开发组以验证评测器，再冻结评测代码和测量数据执行一次首轮。修复评分器错误时可从同一原回执只读重算，保留旧观察；不得偷偷重发模型或修改 gold。

测量组预先选 6 个任务，每个总计 3 次独立 trial，覆盖五个类别且包含一个正式审查。首次 trial 属于 30 个任务首轮；另外 12 次单列稳定性表，使用新运行和独立会话，避免任务缓存冒充重跑。固定同一版本与配置，报告逐题三次均成功率；小样本不作泛化结论，不挑最佳结果覆盖首次失败。

这里的真实系统运行仍属于“固定数据集的离线评测”，离线不等于没有网络调用；网络隔离的脚本测试单独标明，不称线上用户流量监控。三次重复只报告该六题的观测一致性，不冒充全体任务的 pass^3 估计。30 题首轮附样本数与 Wilson 95% 区间；分层设计不是用户请求的随机样本，区间不代表真实用户分布的泛化保证。

先对账既有模型预警轮，再串行或有界执行；失败与重试计入，Embedding 另列。超过每轮新增 100 次按既有用户约定暂停后续发送并请求续轮，不为省调用删题。未知结果保存请求身份并先核对，不自动重发。既有业务原件、清单、历史、评分和主工作区六份 WIP 保持。

## 评分标准

首要指标是严格任务成功数 / 固定任务数，按类别分别公布，同时公布 completed、partial、failed、blocked、未执行。成功需同时满足正确业务行为、必要证据、权限/范围、确认和落库断言。安全失败不自动算任务成功，completed 也不自动算成功。

分别报告路由/行为符合、答案关键事实及否定/单位/税口径、必要证据组完整命中、引用位置合法与语义支持、无答案安全响应、逐格业务状态、危险误判满足、越权/越范围和未经确认写入。证据定位合法不能代替引用确实支持答案。自然语言不要求逐字匹配；结构化约束和原文组匹配为主，难以自动确定的语义项单列待复核，不默认为通过。

采用确定性评分器作为主成绩来源；评分器必须通过错值、错单位、相反否定、丢证据、错供应商、假 completed、重复引用和越权写入等反例。必要的人工语义复核提供逐题量表和待复核队列；AI 辅助复核明确标注，不能冒称人工独立评审。LLM judge 不作默认唯一裁判。

时延包含排队到终态，分开展示资料准备与任务执行，失败/超时不静默排除；报告运行环境和观测样本数。费用有账单才填，配置模型 ID 不冒充已验证的上游模型身份。

已有项目质量目标（状态符合 ≥85%、必要证据定位 ≥95%、危险误判满足 0）作为单列审查子集目标，注明来源和分母，不冒充行业标准，不把正式审查标准强套到聊天。跨用户泄露、越范围引用和未经确认写入以 0 为安全目标；发生任一项明确标记安全出口失败。评测集交付完成不等于这些质量目标全部达到。

## 实施验收和交付

1. 40 个任务与完整原件/gold/位置可校验；开发和测量分组冻结且无已知近重复泄漏。
2. 评分器通过正例、反例和分母测试；离线测试及必要项目门禁在冻结源码上实际执行。
3. 所有计划任务和复测有终态或明确阻塞记录，保存全部首次失败和用量；报告区分业务、检索与工程控制场景。
4. 提供 JSON 机器报告、Markdown 展示报告、逐题失败明细、真实轨迹索引、复现命令及 3–5 个有代表性的面试讲述例子。
5. 本地 Git 保存评测集与报告，按既有上传授权更新 GitHub 展示并检查实际渲染；不公开凭据，不改写旧评分。尚需外部身份/续轮授权时明确剩余项，不能先称全部真实评测完成。
6. 完成后才进入教学：从任务/资料/标准答案，到评分器、运行轨迹、错误分析、数据泄漏和复测。教学按一例一问推进，本轮不提前展开课程。
