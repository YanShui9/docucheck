# 开发流程优化：范围与验收

用户于 2026-10-10 同意一起实施三个大步骤，并要求保留可回滚备份。本设计落实此前已讨论的方案，无新增产品交互或业务功能。

## 目标及取舍

1. 入口精简：当前技术栈、业务约束、API 约定、真实进度保留；三个旧入口归档并修正相对链接。历史数值不得升级为当前质量承诺。
2. 统一开发验证：标准库 CLI 复用现有离线验证器，提供文档检查、变更风险计划、定向/全量/前端检查及只读环境概览。默认不联网，不加载 `.env`，不启动服务，不调用模型，不清理业务数据。
3. 风险审查与度量：交付模板列业务断言、反例、验证范围、未验风险和源码身份；比较文档体积并记录检查耗时。跨任务或不同门禁耗时不能当提效实验。

采用少量脚本和 Markdown。暂不添加 Review Bot、MCP 服务、多模型编排或新的自动部署平台。

## 回滚

修改前创建 `workflow-baseline-2026-10-10` 标签和忽略目录中的完整 Git bundle，校验 bundle 并克隆验证标签指向原提交。每步独立提交；恢复优先使用 `git revert`，避免覆盖后续工作。备份仅为 Git 源码：环境文件、数据库、采购原件没有改动，本步骤不声称完成数据灾备。

## 门禁及边界

- 文档变更检查入口本地链接、代码围栏、失效字符；历史归档逐段保留，仅改相对链接。
- CLI 测试覆盖高风险路径判断、未知代码变更的保守处理、显式测试选择、离线隔离、错误/超时/网络计数、报告不可覆盖及不兼容比较。
- 定向结果只证明指定测试；全量复用 `scripts.verify_offline`，CI 原有全量门禁保持。
- 环境概览列源码及本地依赖，不将其称为服务、登录或业务端到端验收。真实集成与浏览器/模型检查遵循已有显式协议，不伪造自动验收。
- 本轮不应用 0017、不重启运行服务、不改前端或生产数据。
- 文档字节减少只证明阅读素材变少。真实 token、账单、任务提效和回归遗漏需后续同类任务测量。
