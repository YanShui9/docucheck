# PDF 范围外页面显式确认方案

日期：2026-10-25。状态：用户已于本对话明确确认，按下列范围实施；实现、验证及部署结果另行记录。

## 已核实的问题

原合成案例 `dyn-d03` 的 Run `f639cc12e159461a98eee9ebd34a1708` 为 `partial / coverage_incomplete`。两份规格 PDF 均解析完整，但资料关联仅包含第 1 页。两份第 2 页各有 5 个未关联块，包含“其他手机 / DEMO-OTHER”、范围外声明、容量和单价。

使用保存的全部原文块、清单和关联，在固定源码 `4fed2c7c7fa36b8d56046b0f7c3666b84e56e45e`、当前 `dynamic-rules-v15` 下只读重建：计划为 2 个批次，两家供应商的 `phone` 来源完整性均为 false。网络尝试和模型请求均为 0。证据位于本机忽略目录 `data/verification/scope-exclusion-design-20261025/diagnosis-01.json`；这是确定性规划复现，不是新的模型抽取或页面验收。

当前 `ItemBindingEntry` 只能确认品目与来源范围，无法表达“该页经核对不属于任何本次采购品目”。`_bound_review_plan()` 会检查供应商全部原文库存，未关联尾页因可能藏有反证而阻止完整覆盖。既有合同明确保留此保护。因此此处存在范围表达缺口，不能将其当作抽取错误，或仅凭资料自己的范围外声明直接跳过。

## 方案比较

| 方案 | 效果与代价 |
| --- | --- |
| 显式确认排除 PDF 页面（推荐） | 用户可保留多型号原件；新增有限范围操作、不可变确认记录及历史/导出说明，范围决策可追溯。 |
| 要求用户另传只含目标型号的新 PDF | 保持现有代码合同，但需要维护另一份输入快照；属于临时操作方案，没有补齐原件内的范围表达。 |
| 依据页面标题或模型判断自动跳过 | 操作少，但未确认的文本即可缩小正式审查范围；本步不采用。 |

## 推荐方案的本步范围

只补“已经明确采购具体 SKU 时，用户显式排除其他 SKU 的完整 PDF 页面”。沿用现有资料范围确认、权限、事务、幂等、版本及原文定位，不新增模型判断，不扩充规则类型。

首版不支持排除 XLSX 范围、PDF 页内区域、解析不完整文件、无明确具体型号的任务或共同商务条款。复杂/无法可靠匹配的型号继续要求人工核对或拆分资料。

## 页面操作、信息层级与样式

保留现有资料关联弹窗的样式、布局规则和移动端处理。在该弹窗提供次级操作“排除其他型号页面”，不增加独立管理页面。

操作流程：选择 PDF → 选择一页 → 查看该页原文 → 填写其他型号、选择原文型号依据并说明原因 → 加入本次修改 → 在最终确认区核对后保存。

已关联范围、本次待保存修改、已确认排除页分别清晰标注；显示文件名、页码、其他型号、原因。提供“查看原文”和“取消排除”。长原文可展开，不能用只有内部 ID 的提示代替位置。

最终确认文案明确包含：“我已核对关联范围及排除页面；被排除页面不属于本次任何采购品目，也不含适用于本次采购的共同条款。”该操作不会自动勾选。只读用户可查看确认记录；上传/保存中的忙碌状态沿用现有控制，不改变用户的写权限身份。

错误需就地说明页码、型号、重叠范围或版本变化；未知保存结果继续使用原幂等键核对，不静默重发新操作。键盘操作、焦点返回及窄屏滚动沿用现有弹窗合同。

## 服务端范围合同

1. 保存请求增加独立的 PDF 排除项，不把“其他型号”伪装成采购清单中的新 item。每项携带文件 ID、原件 SHA-256、完整解析器版本、单页选择器、其他 SKU、同页原文 SKU 锚点及原因。
2. 服务端展开该页全部原文块并生成来源指纹；客户端或模型不得提交最终排除证据集合。排除页必须存在、有原文且文件解析 complete、无覆盖问题。排除行为不能修复未解析页面、缺失文件或抽取批次失败。
3. 排除仅针对所属供应商原文件，在当前 Case、快照和已确认清单内有效。所有当前采购品目必须有可可靠表达的明确 SKU；排除页须有单一、明确、非否定的其他 SKU，且与采购 SKU 和该供应商已确认的目标 SKU 均不相同。
4. 锚点须来自该页，且原文全文不能出现当前采购 SKU、其他已采购品目或明确不同的另一 SKU。型号声明复杂、未知、混合，或原文明确表示条款对本次/所有产品共同适用时，拒绝排除。有限原文检查不能证明任意自然语言无关；最终范围决策仍来自用户明确核对，界面与报告不能称其为系统自动证明。
5. 排除页不得与任何已关联事实范围或归属锚点重叠；重复页拒绝。删除关联、排除和新增操作作为一个完整版本在原 Case 锁下校验并保存。请求容量继续有界；排除页数量不超过既有单任务 PDF 30 页上限，全部证据集合仍计入既有范围容量。
6. 未确认或取消排除后，原文仍按未关联库存处理。未知尾页、未关联文件、同页混合内容及可疑共同条款继续阻断完整覆盖。被排除页不得成为抽取输入或事实引用，但原件与原文块保持可查。

## 冻结、规则版本和回读

- 继续使用现有不可变关联版本 JSON 保存确认人、时间、原因和内容摘要，拟为包含排除项的内容采用 `schema_version=2`；现有 schema 1 回读及摘要字节不变。预计无需新增业务表；以实现前的实际存储约束核对为准。
- 新行为使用独立的 `dynamic-rules-v16`，继承 v15 金额/来源语义；v15 及更早版本仍按原库存覆盖规则回读。schema 2 不得交由旧规则处理或默默丢弃排除项。
- Run 固定关联版本与内容摘要。批次、输入、检查/事实与缓存身份依照新规则及关联摘要分离；缓存、历史、修正和导出重新核验来源指纹，不能以新确认补齐旧 Run。
- 供应商库存仅在“已关联事实范围 + 既有纯身份锚点豁免 + 当前有效的显式排除页”覆盖全部原文时通过；解析与全部抽取批次仍须分别完整。
- 首版不在清单新确认后自动续用含排除项的版本，即使品目名称看似未变；提示重新确认范围。原先不含排除项的版本续用合同保持。原件、解析器、快照、品目或供应商变动使新排除失效。
- API、JSON、Excel 和报告均显示排除的文件、页码、其他型号、依据及确认记录；“正式结果”表示在列明的确认范围内完成，不能让导出读者误以为排除页也接受了事实审查。旧报告和旧评分保留原貌。
