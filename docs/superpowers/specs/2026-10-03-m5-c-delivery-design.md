# M5-C 复现、离线 CI 与面试交付设计

用户已确认 M5 三个大步骤，并于 2026-10-03 授权开始 M5-C。沿用该范围：补交付工具与文档，保持 fields-v4 业务契约及 M5-B 历史分数。采用 GitHub Actions 与本地同命令校验；公开资料/部署形态及前端视觉没有新增设计。

## 设计选择

1. **GitHub Actions + 本地脚本（采用）**：Python 3.12、锁定全部依赖、显式中文字体、网络阻断的离线测试；现有前端单元测试与构建另一个 job。Action 引用固定 commit，权限 contents:read。
2. 外部托管评测平台会增加账号和运行依赖，不适合本次复现交付。
3. 仅保留本机命令无法形成自动回归入口，不能满足本阶段 CI 条件。

## 工具边界

- `scripts.offline_guard` 作为显式 pytest plugin，在收集之前阻断 TCP/DNS 请求；即使业务捕获异常，也在会话结束按阻断次数判失败。MockTransport、内存 SQLite 与 TestClient 保持可测。普通显式 MySQL/实时模型测试不加载此插件。
- `scripts.verify_offline` 统一清除外部集成 opt-in、凭据和跟踪变量，验证字体和 Python 版本，执行 pip check、Ruff、隔离 pytest，输出带执行结果的报告。网络安装依赖属于准备步骤，测试阶段无外部请求。
- 依赖锁来自实际主机/worker版本和依赖元数据；共同依赖优先使用已运行 worker 的版本。干净环境安装后实际执行 pip check/回归；不把旧环境版本冒充新锁验证。
- `evals.delivery_bundle` 默认预览。显式 build 只收录合成 corpus、AI复核记录、明确选定的历史/最终报告、版本清单与交付文档；不遍历上传目录、凭据或数据库。
- ZIP manifest 为每个条目记录 SHA-256 和字节数。verify/restore拒绝路径越界、符号链接、大小写重复、未知条目、错误哈希、超限和凭据字段；恢复只到全新目录，不能覆盖当前数据库或 data。
- 演示分为离线回归、历史实测回放、显式付费模型实演。三种成果分别说明；历史回放不能称现场重新推理。

## 交付与验证

新增工具按测试先行实现；再用无 .env、无原 data、无 node_modules 的新目录/隔离环境执行安装与校验。前端执行已有测试与构建。检查归档和恢复后的资产哈希、报告与版本数字。业务源码指纹仍应为 M5-B 的 f3938cda…；若实际改变，必须单列版本和所需回归。

最终交付启动/备份恢复文档、10分钟演示流程、架构图与追问解释、运行记录和真实限制。GitHub workflow只报告配置和本地等价校验，未推送/未运行远程job不声称云端CI已绿。独立封存0、费用未知、企业生产验收未完成继续保留。
