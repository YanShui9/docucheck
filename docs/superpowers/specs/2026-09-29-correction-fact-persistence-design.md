# M3-11a：修正前的可复核事实集持久化

日期：2026-09-29。用户选择只允许修正有原文支持的提取事实。本规格是人工修正的第一段后端基础，不开放修正提交接口。

## 背景与边界

现有 `AgentSession.tools.fact_sets` 在运行期间保存经来源验证的事实，但 Run 持久化的 `memory_json` 只有核验结果，没有事实。直接改历史结果会破坏审计；每次修正重新调用模型会引入费用和不确定性。采用追加修正记录、生成新版本、使用已验证事实确定性重算的方向。完整修正 API、版本创建和规则重算属于后续独立小步。

本步只持久化当前 Run 已生成的事实集。不会改变模型提示、业务判定或现有 API 答复，也不会调用模型。

## 契约

1. `memory_json` 升至版本 2，保留版本 1 的读取兼容。新增 `fact_sets`，只保存 `FieldFactSet` 和内存字段的 `FactSet`，数值以十进制字符串保存，保留来源 ID、快照、供应商、字段、扫描范围和覆盖状态。
2. 保存时只取每个供应商与字段的最新事实集，最多 24 组；每组最多 256 个事实和 25,000 个扫描来源 ID，整个事实集 JSON 不超过 512 KiB。超出时不保存事实集，并标记 `fact_sets_available=false`；原有核验结果仍可持久化。
3. 恢复时重新检查快照 ID、仓库指纹、供应商、字段、每个证据 ID 的归属、事实数值和规则正规化，以及扫描 ID 是否在同一快照的适用范围内。不通过则报 `memory_scope`，不能向模型或规则提供伪造事实。版本 1 历史记录仍按原逻辑恢复，视为没有可供修正重算的事实集。
4. `fact_sets_available` 仅表示本次记录可用事实是否完整保存，不代表整份资料解析完整，也不改变五种业务结论。未来修正提交若无可用事实，必须显示待重新审查，不能编造重算结果。

## 验收

- 离线测试覆盖新旧版本恢复、字段与内存事实集往返、跨供应商/跨快照/不存在的证据引用拒绝、篡改数值拒绝，以及超限时安全降级。
- 保持现有后端回归、Ruff 和依赖检查通过。此步不操作 Docker，不请求 DeepSeek。

参考：[Microsoft 追加事件的审计与复杂度权衡](https://learn.microsoft.com/en-us/azure/architecture/patterns/event-sourcing)、[SQLAlchemy 版本控制边界](https://docs.sqlalchemy.org/en/20/orm/versioning.html)。完整事件溯源框架对本地单用户项目过重，因此只为人工修正保留不可变审计记录。
