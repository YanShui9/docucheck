# 动态多品类评估设计（D1）

日期：2026-10-11。基线：`eb67ded`。范围：资料与评分协议设计；未新增生产行为、生成采购原件或执行模型评估。

## 1. 要回答的问题

用户描述手机、水果、服装或混合采购时，系统能否识别动态指标，经过明确确认后，按供应商、采购品目、型号与证据口径给出可追溯结果？失败、未知用量、人工复核和历史版本是否如实显示？

品目对应 C 的指定合成闭环已完成，见[C 报告](../../document-item-binding-c-acceptance-2026-10-11.md)。这只能证明该协议下的路径，不是多品类独立准确率。旧 M5 的 104 个判例属于固定八字段设备版本。

## 2. 资料路线与取舍

| 路线 | 可取之处 | 限制 | 本轮决定 |
| --- | --- | --- | --- |
| 公开需求作为场景参考，另写合成需求及供应商响应 | 来源可查；可以覆盖冲突、缺失、包装与条件承诺；适合个人开发者 | 合成且作者已见，不能称独立真实采购质量 | 采用，先做开发集 |
| 直接用公开需求与真实响应成对资料 | 更接近实际交易 | 本轮核实的公告未提供可确认配对的完整供应商响应及逐项答案 | 保留入口；取得完整资料与使用条件后单列 |
| 使用现成文档/采购问答基准 | 可参考定位、分层报告与评分格式 | 通常不包含本产品的动态清单、品目绑定和正式采购判定 | 借鉴方法，不换算成产品成绩 |

本轮实查的[保山市水果采购公告](https://www.baoshan.gov.cn/info/3281/10365304.htm)使用折扣率和预计费用；[烟台大学服装采购公告](https://sofl.ytu.edu.cn/info/1032/4402.htm)区分预计数量与最终结算数量，并要求样品和证明文件。二者只有需求正文及附件入口得到确认，附件内容没有取得；附件名称不证明已经存在供应商报价。联系人等个人信息不进入新样例。

[DocILE 官方仓库](https://github.com/rossumai/docile)提供字段定位/行项目抽取及其评估方法，获取数据需要另行取得下载 token；本轮没有下载数据。仓库的 MIT 代码许可不自动等于全部数据的再分发许可。[procurement-benchmarks 仓库](https://github.com/kundanshar-cell/procurement-benchmarks)的问答结构可参考，其采购分类/ERP 问答不能替代本项目的中文原件审查。未采用星数作为质量依据。

逐条核实状态见[来源目录](../../../evals/dynamic/source_catalog.json)。本次查找范围内未确认可直接使用的中文“需求＋完整供应商材料＋动态判定 gold”基准；不据此断言网上不存在。

## 3. 资料身份与独立性

- D1 写出的[12 包蓝图](../../../evals/dynamic/case_matrix.json)共有 55 个动态指标定义、104 个供应商判定位置，全部 `ai_authored_seen_development`。蓝图是计划，不是已经取得的原件、逐格 gold 或测量成绩。
- D2 将每包做成支持的 PDF/XLSX 原件、来源 manifest、确认用清单、品目对应与评分侧 gold。每份合成文档显式注明虚构；不模拟真实机构签章、证书真实性或真实成交。
- 需求、供应商响应、gold 的作者/复核者及是否见过结果分别记载。先固定原件与逐格答案，再运行产品；不得调用产品规则或用模型输出反推 gold。
- AI 写过、看过或复核过的包不能转成独立封存包。本轮独立封存数量仍为 **0**。原目标是总评估至少 12 包/104 判例且至少 6 包真正独立封存；本轮 12 包开发蓝图只满足规模准备，独立部分仍需新来源/独立作者与复核者。后续取得的独立包另外加入，分母重新冻结，不能拿开发包改标签冒充。
- 划分按采购项目/来源家族进行，同一公告改数字、换排版、换供应商名的变体留在同组。执行人员只取 `inputs/` 与确认的业务配置；`gold/`、审查意见、标签及评分报告不得作为 Agent 输入或向量库内容。
- 网络来源只提交 URL、核实日期、状态及短摘要；未取得文件不填写 SHA。原文保存/下载和再分发前核对使用条件；原始第三方材料默认在忽略的 `data/`，不随 Git 上传。

## 4. 动态身份与评分边界

评分主键为 `(pack_id, supplier_handle, item_id, criterion_id)`。型号/SKU、清单版本、资料快照、绑定版本分别记录，不能用名称或 SKU 代替品目 ID。每包供应商与启用指标的笛卡尔积在运行前展开并冻结；本蓝图合计 104 个位置。

旧工具 `evals/m5_metrics.py` 从 `FIELD_NAMES` 生成供应商×固定字段分母，`candidate_corpus.py` 的 gold 使用 `FieldKey`。保留它们做历史回归。D2 新增 `evals/dynamic/` 契约及评分器，不能在旧报告上套新的含义，也不能只用回答文本匹配旧八字段名称。

六类规则沿用 `backend/app/criteria/models.py`：`numeric / money / enum / presence / duration / manual`；数值是十进制字符串。蓝图清单按现有 `ChecklistDefinition` 校验，但仍是未保存、未确认的评估业务输入草案。

### 业务处理界限

- 预计数量不等于已确认订单数量；规格可选范围不等于选定型号；不得编造分尺码数量。
- 折扣率可作为有明确口径的 numeric 指标，但没有市场基价时不能换算金额。箱/袋/件不能无依据相互换算，外币/未含税价格不能直接比较含税人民币金额。
- duration 仅支持自然日、工作日、月及明确起算事件。小时、绝对日期、不同起点或日历的转换本轮走 manual；不为提高通过率扩展规则。
- presence 只核验适用材料是否存在；“承诺将提供报告”不能当已附报告。附件存在不证明证书真实有效、商品安全或法律合规。样品验收、感官新鲜度和外部资质核验均为人工业务边界。
- 同一范围/型号/口径的相斥值应保留冲突；不同包装、批次或型号要先判断是否可比较。正式“证据不足”要求解析/全量抽取及范围覆盖完成；partial 不能改写成缺证据。
- manual/附条件指标应保留需人工确认；人工只修正有原文支持的提取事实，不能直接把最终结果改成满足。

## 5. 四条评估轨道分开

| 轨道 | 输入 | 输出与验证 |
| --- | --- | --- |
| 指标候选 | 需求原件/用户要求，不带答案 | 必要指标召回、规则/阈值/单位/口径一致性、无据新增、确认前不生效；IDs 可经人工建立一对一映射，歧义不算成功 |
| 正式审查（主轨） | 已独立于产品确定、保存确认的清单和品目对应 | 每个冻结主键的处理/业务状态、正式标记、所有必要证据及可见回答/导出一致性 |
| 检索问答 | 单独写的中文问题及可接受证据集合 | BM25/向量/hybrid 的 Recall@5、跨品目/跨供应商误用、降级及来源支持；不把 top-k 无命中当正式缺失 |
| 可靠性与权限 | 越权、范围、解析失败、超时、未知请求、显式重试和历史变更脚本 | 拒绝/降级/partial/只读等先约定断言；与 104 格业务准确率分开 |

主轨先采用固定确认清单，避免“模型生成的指标恰好适配模型输出”造成自证。候选质量另行测量，同一包两条成绩不合并。历史版本、人工继承和失败分支可复用该包原件，但不额外扩大主轨分母。

## 6. gold 与必要证据契约

D2 每格必须在运行前有：主键、预期处理状态（主轨为 complete）、五选一业务状态、预期正式/人工标记、业务理由、必要证据组、允许定位、全文覆盖范围及人工复核记录。另记规则口径、买方基准和来源版本。

证据组是“组间全部满足、组内任一允许等价定位”。例：冲突需要需求基准、报价的值、规格的相反值三个组；不能只找到其中一处就得满分。需求阈值和供应商承诺分别定位，不能用买方要求证明供应商满足。PDF 定位页/可用 bbox，XLSX 定位 sheet/cell；同时核对文档 SHA、角色、供应商、品目范围和原文。

缺失类 gold 列出必须完整检查的适用文件/范围；评分侧复核无适用供应商证据，并核对产品覆盖记录，不用空引用替代覆盖。对于证书等材料，gold 只写“材料存在性”或“待人工核实”，不写真实性结论。

禁止运行后改答案来提高分数。确实发现标注错误时，保留旧 gold、理由、复核记录、版本与该轮成绩；新版本重新运行，不覆盖旧报告。

## 7. 计分与预定门槛

| 指标 | 口径与目标 |
| --- | --- |
| 严格任务成功 | 完成全部预定格、身份/状态/证据/可见输出均正确的包数 / 固定包数；不把 HTTP 200 当成功 |
| 主轨业务准确率 | 处理完整、正式性正确且业务状态正确的格 / 冻结总格数；目标 ≥85%；漏格、错 ID、partial/failed 仍占分母并算错 |
| 必要证据定位率 | 全部必要证据组均正确定位的确定性结论格 / gold 中预定确定性结论格；目标 ≥95%；分母运行前固定，不因产品失败缩水 |
| 危险误判满足 | gold 不是“满足”却出现正式、可见回答或导出“满足”的次数；目标 0；即使接口状态正确而回答错，也记录危险误判 |
| 引用与范围 | 有效引用 / 全部引用，同时列错引用、遗漏证据组、跨品目/供应商及历史来源误用；无引用任务不能报 100% |
| 处理与人工状态 | completed/partial/failed、非正式/待复核分别统计；业务五状态混淆表及品类/规则分组展示，未完成另外列出 |
| 任务轨迹 | 首次成功率、失败原因、显式重试次数/结果、取消/中断/未知请求；首次结果不被重试覆盖 |
| 用量/时延 | 实际/未知调用与 token 分列；费用需实际账单，不按猜测价格填；排队、服务、端到端计时范围各自注明 |

确定性定位分母使用 gold 预定的“满足/不满足/资料冲突且有必要来源”的格；证据不足的完整覆盖和待人工确认的引用另列，不与该率混淆。所有率同时列分子/分母。重复判例、额外返回格、未预期的供应商/指标单列并导致严格任务失败。

104 格开发集目标不是独立发布质量门槛达标声明。独立集单列，不汇总成一个看似更高的成绩。生产容量、恢复、取消边界在后续步骤另测，旧五文件 120 秒协议不迁移到不同负载。

## 8. 执行身份与副作用

冻结顺序：输入原件/manifest SHA → 清单与对应 → gold/复核记录 → 协议版本 → 运行源码/依赖/模型/解析/Embedding 配置 → 预览 → 明示发送 → 原始响应及独立评分。实际环境未知项写 unknown。

离线命令不读 `.env`/令牌，不联网、不启动服务、不覆盖报告；输入和 gold 分目录，路径/大小/哈希预检。真实 HTTP 运行仅针对新建合成工作区，保存资源 ID、每次 attempt 和原始失败；不自动 retry 已发送或 outcome_unknown 请求。开始实连前按协作约定说明 Docker/模型及预算，用户未提供实际账单时费用保持未知。
