# M4 采购审查工作台设计

状态：用户于 2026-09-30 确认“专业审查工作台”方向和整体交互；执行节奏见 [四个大步骤](../../m4-large-step-plan-2026-09-30.md)。

## 使用场景

企业内网单组织、多账号演示。采购经办人建立 Case，按需求、报价、规格书上传 PDF/XLSX，绑定供应商；在同一 Case 内提问、发起完整八字段审查、追问来源，并查看不同快照的结果。人工只修正原文支持的提取事实，同源旧新值冲突保留人工复核标记。管理者可以回看审计轨迹和导出。当前先用本地 OIDC 演示账号，正式部署可接企业 SSO。

## 页面与交互

工作区采用左侧 Case/资料导航，中间“对话”和“核验矩阵”双视图，右侧可调整宽度的原件证据面板。上传表单明确文档角色、供应商和型号；列表展示解析状态、覆盖问题及所属快照。对话显示当前模式、Run 生命周期、澄清、取消、重试、来源卡和模型发送范围。矩阵按供应商 × 八字段展示判定、理由、证据及快照；单击证据可在原 PDF 页标示坐标或定位 XLSX 工作表单元格。修正、复核、历史与导出都保留快照上下文。

桌面以矩阵和证据并排为主。窄屏使用分层页面和全屏证据面板，矩阵允许横向滚动，列标识保持可见。所有状态用文字和图标表达，不仅依赖颜色。键盘可到达导航、表格格子、来源和修正操作；焦点可见。异步操作有空、加载、错误、部分完成和过期状态。旧快照答复不能标作当前正式结论，`partial`、`failed`、`interrupted` 也不能显示为已完成判定。

视觉采用灰白背景、深蓝灰正文、克制的蓝绿主操作色，中等信息密度。状态色单独定义，保留足够对比度与中文阅读字号。页面不展示模型内部思考、密钥或未经净化的原文 HTML。

## 应用边界

前端使用 Vue 3、TypeScript、Vite；页面负责交互、轮询和展示，后端负责身份、授权、快照、规则结果与导出。PDF 使用 PDF.js 读取经过授权的原件；XLSX 来源由后端给出工作表、单元格和原文值，前端只读呈现。前端不从 Agent 的自然语言答复反解析结构化结果，也不计算正式判定。

API 在 OIDC 模式验证访问令牌签名、算法、发行者、受众和时效，并根据持久化项目成员关系检查 Case 及所有子资源。项目角色暂定 owner、editor、viewer：owner 管成员和删除，editor 上传、提问、修正，viewer 只读。未授权对象统一返回 404，缺少或无效身份返回 401。开发兼容模式只允许本机演示，不能作为共享部署的默认安全边界。Keycloak `start-dev` 仅作为本地 OIDC 演示服务；部署方需另行配置生产身份服务。

M4-B 建立身份、项目/Case 归属和工作区资料入口。M4-C 暴露版本化结构化 CheckResult 与授权原件读取，接对话、矩阵、证据和修正。M4-D 用同一快照结果导出 JSON/XLSX，验证公式注入防护和完整闭环。数据、权限与结果契约的具体文件见 [四步计划](../../m4-large-step-plan-2026-09-30.md)。

## 验证

后端验证跨账号直链、不同角色的读写、旧快照/删除态和 Run 子资源访问；前端验证上传绑定、状态切换、来源定位及空/错/部分状态。M4 完成前执行真实 MySQL/OIDC 演示闭环，真实 DeepSeek 请求另行说明发送资料范围与成本。独立真实资料质量、成本、性能和正式部署恢复门槛留给 M5。
