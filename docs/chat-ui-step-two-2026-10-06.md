# 聊天前端第二大步交付：动态指标与审查报告

日期：2026-10-06。按已批准的 [三大步计划](superpowers/plans/2026-10-05-chat-ui-implementation.md) 完成第二步。

## 已实现

- **ChecklistPanel（审查要求面板）**：头部新增"审查清单"入口；候选卡片（`changes`/`proposal`）显示品目/指标概览与"查看与编辑"。面板按品目分组展示完整清单，六类规则可视化（数值/金额/枚举/资料存在/期限/人工复核），来源标签区分"需求原文/用户设置"，原文依据可展开并跳转 EvidencePanel。支持增删改指标（新建品目、规则表单、本地校验）。
- **保存与确认两步协议**：保存草稿（PUT，完整 definition + 两个 revision + 幂等键）后明确提示"尚未确认"；确认对话框列出品目数、指标数、资料版本；部分确认只对勾选项生效并展示排除项。确认前按钮禁用（无草稿版本时），保存成功不等于确认成功。
- **资料升版处理**：快照升版后清单进入"需重新确认"状态，提供"以上一版确认为底稿"（读取上一确认版本填充编辑器）；历史版本只读。
- **ReviewPanel（审查报告面板）**：`review` 结果显示"查看完整报告"；矩阵行按品目分组的已确认指标、列为供应商（显示持久化中文名称）；六类业务状态 + 正式/非正式标记 + 中文原因；部分完成显示批次进度（已核验/计划）；单供应商明细切换；宽矩阵横向滚动；历史结果醒目标注资料版本。
- **事实修正与审计联动**：报告内直接选择提取事实提交修正（复用原事实 evidence_refs/quote 与 payload_digest），成功后显示"需人工复核"审计卡；审计列表读取 `GET /agent-runs/{id}/fact-corrections`。
- **导出联动**：Excel 主按钮 + 审计 JSON 折叠菜单，复用既有导出接口。
- **供应商中文名称**：文档读取响应新增持久化 `supplier_name` 字段（`list_current`/`list_snapshot` + `DocumentOut`），报告列与事实选择器使用持久名称，不使用刷新即失的临时映射。
- 事实选择器将 criterion_id 解析为指标名称（checks 映射回填）。
- 样式沿用聊天设计变量（低饱和绿、白面板、12px 卡片、状态用文字+颜色），新面板纳入既有的窄屏覆盖/并排布局。

真实模型调用：本轮闭环约 3 次有效请求（候选 1 次、审查 2 次含一次等待澄清被取消），另有 1 次因资料版本过期产生的空跑被前端拒绝、未到模型。实际账单金额未知。

## 边界与说明

- 供应商报价通过 HTTP API 上传（浏览器内嵌框架不支持文件选择器）；上传后的解析、轮询、审查、报告全部走真实页面/队列/模型。真实 UI 上传路径在第一大步已验收，本次未重复。
- 首次发送审查请求时资料版本尚未被页面感知，触发了设计的 revision 冲突提示；点击"刷新状态"后正常。该场景由旁路上传造成，UI 内上传不受影响。
- 演示数据库中 vendor-a 的历史同名词（"Vendor A" 等）被统一更新为"示例供应商"，均为本地合成测试数据。
- 面板焦点/键盘返回、长历史渐进分页、记忆偏好设置为第三大步范围。
- 浏览器验收未覆盖移动端截图（沿用第一大步响应式布局与媒体查询）。
