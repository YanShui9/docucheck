## 变更与约束

1. **可选配置**：保留可选/选配/未声明实装的数值和原件引用，限定语为 unknown，不能作为实装容量。模型与一次补查之后，可用同一原文验证器保留明确不确定的数值跨度；未扫描或 schema 失败的批次仍不完整。
2. **金额口径**：fields-v4 允许无计价单位的金额，如含附件套装总价60000元。保留60000、元/CNY与未知计价单位，不除采购数量、不添加元/台，结果待确认；裸币种不能截短原文中的元/台。v1/v2/v3审计重放继续拒绝其旧契约不支持的裸币种，保留实际交期版本逻辑。
3. **其他型号**：只对整段明确“另一型号 + 型号ID + 已装内存 + 不属于本次报价”、与已绑定型号不同的文字作确定性排除；缺绑定、同型号、缺排除声明、混合当前型号及附带文字均不排除。原件仍扫描并可读取；验证器禁止将其作为本次型号事实。
4. **事实记忆**：恢复 complete 集合时重新检查原文数值及严格相邻单元格关系，不能仅信任 complete 标记、scanned_ids 或客户端可重算的集合哈希。
5. **审查进度**：完整八字段审查的既有约束扩展到明确指定的一家或多家，使用统一 QuestionScope；普通字段问答与来源追问不强制全矩阵。全量抽取、规则核验、最终提交按实际覆盖推进；未覆盖最多补抽一次再保留partial。不是靠放宽 token 或无限重试完成任务。

这仍是模型负责受控工具规划和原文事实提取、服务端负责范围/覆盖及采购规则的混合工作流。限定语、引用和正式结果不能由模型自行确定。结构化输出的 schema 与验证错误处理参考 [LangChain 官方说明](https://docs.langchain.com/oss/python/langchain/structured-output)，具体业务原文校验由本仓库实现。
