# 当前开发协作协议

更新：2026-10-10。用户已批准流程三步一起实施；[旧小步全文](archive/2026-10-10-step-by-step.md)保留历史。当前用户授权优先，目标明确后持续推进，不重复请求已获确认。

## 一次交付

1. 读取入口、当前计划、相关代码、Git状态，历史按需加载。
2. 明确目标、影响面、业务断言和未知点。小改动直接处理；主要前端方向或影响验收的未知点先讨论。
3. 最小实现，新增行为补失败回归。开发中相关测试，交付补必要门禁。
4. 沿业务路径审查；新增机制说明必要性、可替代方案；发现须有位置、触发输入、违反契约和验证证据。
5. 核对结果/来源/版本/落库，报告未验证项，更新状态，独立Git提交并推送。

## 风险与门禁

| 风险 | 示例 | 验证 |
| --- | --- | --- |
| 低 | 文案/文档 | 链接/格式/diff；资源影响构建则补构建 |
| 中 | 模块内部行为/前端交互/开发工具 | 相关回归、类型/构建；交付必要全量 |
| 高 | 权限/证据范围/确认/规则/状态/幂等/重试/数据库/迁移/配置/队列/依赖/CI | 失败/越权/并发反例、全量及受影响隔离实连；部署/回滚另列 |

风险计划是建议，不能自动免除CI。未知代码变更保守高风险；CRUD涉及授权/租户/版本仍高风险。

## 证据与边界

- 业务预期先于实现确定，系统返回什么不等于正确答案。
- 源码/服务/模型证据分开；skip不算通过，合成向量不证明召回，已见开发集不证明独立质量。
- 报告包含源码/脏工作区身份、门禁/测试选择、Python/系统/依赖身份、退出码/耗时/网络计数及未验证项。
- 工具默认离线、报告不可覆盖；不读取.env、访问业务库、启动服务、安装依赖或调用模型。外部操作按既有约定先说明。
- 真E2E需真实浏览器或HTTP业务入口并核对后端状态。健康检查/进程内TestClient不能单独叫E2E。
- 不固定增加多模型、多Agent或Review Bot；稳定操作先脚本化，重复流程确有收益再Skill化。
- 每步解释修改、原因、验证、限制，以及面试时如何讲清核心设计。
