## MinerU 选型核对

MinerU 4.0 的[官方快速入门](https://github.com/opendatalab/MinerU/blob/master/docs/en/quick_start/index.md)将 Python 3.12 作为可行起点，给出的无状态转换入口为 `mineru-kit parse`。已在独立的 `docucheck-mineru` conda 环境安装 MinerU 4.0.7；`mineru-kit version` 输出 MinerU 4.0.7 / Python 3.12.14，`pip check` 输出 `No broken requirements found`。通过直接调用环境内的 `mineru-kit.exe` 运行；`conda run` 遇到中文帮助输出中的非法 GBK 字符时会在 Conda 自身报 `UnicodeEncodeError`，不是 MinerU 解析失败。

对开发样例运行 `mineru-kit parse <pdf> -o <output> --tier basic --ocr-mode txt`。首次需求 PDF 调用包含模型文件下载，约 50 秒；后续同一机器上规格 PDF 调用约 11 秒。日志报告模型推理时间分别约 2.62 秒和 2.46 秒；这不是完整任务耗时或正式性能测量。Basic 的 Markdown 保留了八项需求与四项供应商规格的独立行。`--format middle_json` 输出的 schema 为 `docvortex.middle` 2.0：`pages[0].page_idx=0`；每条对应事实有归一化 `bbox`；页面尺寸在 `extensions.docvortex_layout.pages[0]`，约 595×842 pt。与人工标签逐条比对，12/12 个 PDF 证据片段可在 Basic 文本及带 bbox 的块中定位。

另以 `--tier flash --ocr-mode txt` 解析两份 PDF：12/12 个 PDF 证据片段仍可在文本中找到，但相邻字段行被连接在一起。Flash 的日志模型推理时间约 0.14 秒/页；这两次命令并行执行，不能据此比较端到端耗时。此简单开发样例不足以证明复杂表格或正式验收质量。

安装包自带的 `mineru-4.0.7.dist-info/licenses/LICENSE.md` 已核对：它以 Apache 2.0 为基础，另有商业阈值与在线服务标识条款，内容与当前[官方许可证页面](https://github.com/opendatalab/MinerU/blob/master/LICENSE.md)一致。首版是本地单用户工作台；未来若改变服务形态，需要再复核许可义务。
