# M2-2g：XLSX 隐藏行列覆盖检查（2026-09-27）

本步修复 XLSX 隐藏或零尺寸的行列仍被读取为证据、解析状态却返回 `complete` 的误判。只修改后端解析、离线测试和项目进度记录；没有调用模型 API、启动 Docker、安装依赖或修改前端。M2-2 整体仍未验收。

## 第一步：复现误判

构造包含 `B2=32 GB` 的报价表，分别隐藏第 2 行、隐藏 B 列、分组隐藏 B–D 列。原解析器保留了 B2 证据，却均返回 `complete`。工作表默认隐藏行（`zeroHeight=1`）、显式零行高与零列宽、默认行高与列宽为零也出现同样误判。新增测试先确认这些失败，并以显式可见且尺寸为正的行列作对照。

## 第二步：修正解析覆盖

`parse_xlsx` 在现有工作表 XML 扫描中检查 `<row hidden>`、`<col hidden>`、`<sheetFormatPr zeroHeight>`，以及相关行高、列宽的零值。发现后保留原单元格证据，记录工作表和行号或列范围，并将解析状态标为 `partial`。对负数、无效或非有限尺寸则拒绝文件，避免异常元数据被判为完整。解析版本增加 `/visibility:1`；非 `0`/`false` 的隐藏标记保守视为隐藏，可能使异常标记触发 `partial`。

## 第三步：离线验证

隐藏行、单列、列范围、默认隐藏行、四种零尺寸情形，以及行列分别在可见和隐藏状态下的负尺寸情形均有回归；普通可见行列保持 `complete`。后端全套测试 **144/144 项通过**，所改后端文件的 Ruff 和 `pip check` 通过。全仓 Ruff 仍在未修改的 `scripts/build_dev_pdfs.py` 报导入格式问题；对本步之前的 Git 版本中同一文件检查可复现，属于本步前已有问题。

## 边界与下一步

`partial` 表示当前证据无法证明隐藏内容已按用户可见范围处理，不会丢弃已读取的单元格。隐藏工作表目前仍会被读取并可能返回 `complete`，下一小步拟处理该边界。线程批注、任务级限额和 PDF 无框表格语义仍待后续处理；本步不宣称 M2-2 完成。
