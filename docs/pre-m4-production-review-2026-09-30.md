## 本轮可复现问题

| 优先级 | 问题和影响 | 处理或验收要求 |
| --- | --- | --- |

| P1：已修复待总回归 | `retry` 可在同一会话已有另一个活跃 Run 时重新排队，导致并行模型任务与上下文竞争。 | `RunRepository._new_attempt` 与 `submit` 共用同一会话互斥约束；回归先失败后通过。 |
| P1：已修复待总回归 | HTTP 曾接受 2,001–10,000 字提问，Agent 仅允许 2,000 字，后台重复失败。 | API 和 repository 与 Agent 统一 2,000 字上限，入口返回 422/明确错误，不创建 Run。 |
| P1：已修复待总回归 | 取消或删除后执行中的 Agent 未读取持久状态，仍可能继续发送资料和计费。 | 每次决策/工具/模型调用前和模型返回后校验 attempt/fence；已发出的单次请求无法撤回，Provider 请求仍受 30 秒超时约束。取消回归须证明没有下一次模型调用。 |
| P1：已修复待总回归 | Case 版本在 Run 执行中改变时，旧 Run 最终写入虽被拒，但此前仍可能继续发模型请求。 | 执行中的有效性检查同时核对 Case 当前版本和删除标记；版本变化后的下一次预算检查停止循环。 |
| P2：已修复待总回归 | 上传新版本后旧 `queued` Run 无法领取，也不会被旧的 maintenance 回收，状态永久悬挂。 | maintenance 将旧版本排队任务转为 `interrupted/snapshot_changed`，终止待派发事件；旧结果不成为新版本结论。 |
| P2：已修复待总回归 | PDF 解析器尚未配置时，后台会领取 PDF 并永久标 `failed`；后来配置解析器也不会自动续做。 | 缺少解析器时保留 `pending` 且不消耗 attempt；解析器可用后再领取。另需增加运维告警，避免长期待处理无提示。 |

## 尚未完成的生产能力

1. **身份与隔离。** 企业内网多人版建议在 API 验证 OIDC/SSO 身份，在数据库持久化租户或项目与 Case 的归属；所有 Case/文档/证据/会话/Run/修正/删除查询按同一授权上下文过滤。直接访问底层资源 ID、跨项目并发及删除应有负例测试。公网多租户还需更严格的租户资源配额和运营防护；单机单人目标可采用不同边界，但必须限制本机访问。
2. **资料存储与处理。** 当前 `data/` 绑定本机文件系统，上传文件先落盘后入库；进程崩溃可能留下孤儿文件。正式部署需要持久对象存储或受控共享存储、原件与数据库一致性对账、加密与权限、病毒/恶意文件处理、解析进程隔离及明确的 PDF/XLSX 资源配额。上传请求还需入口层总请求体限额；应用的流式 10 MiB 检查不能代替入口限制。
3. **可靠性与恢复。** 给 API、解析 worker、dispatcher、cleaner、Agent worker 定义 readiness/活性和告警；演练 MySQL 备份与恢复、Redis 丢消息、worker 强杀、模型超时、文件存储暂不可用、迁移失败回滚。MySQL 官方将备份与恢复作为独立运维能力，当前本机卷不等于备份：[MySQL 8.4 Backup and Recovery](https://dev.mysql.com/doc/refman/8.4/en/backup-and-recovery.html)。
4. **可复现交付。** `pyproject.toml` 目前没有应用依赖声明，运行依赖分散在 Conda 和 worker requirements；需要明确开发、测试、生产一致的锁定策略、镜像版本/摘要、CI 离线测试与迁移检查。将服务配置、密钥和部署文档从本机 `.env` 调整为目标平台的密钥管理和发布流程。
5. **Agent 生产评估。** 把 Run 终态、引用正确率、危险误判、工具失败、token/费用/时延按同一版本记录；独立封存集和多次真实调用按路线图 M5 验收。结构化日志和追踪不能记录 API key 或整份敏感原文；模型提供方的数据发送范围和保留策略须由部署方确认。

- 五个新旧问题的定向离线回归在修复前分别给出预期失败，修复后 **5 passed**；追加的“运行中 Case 版本变化”回归也先失败，单项复验 **1 passed**；最终取消与版本检查组合复验 **2 passed**。

## M4 入口与执行顺序

1. 确认部署形态和身份来源，并把权限模型写成 API 与数据模型契约。**在此决定前不实现共享部署认证，也不把现有 API 暴露到非本机地址。**
2. 完成本轮状态机/解析修复的全量离线测试、Ruff 与 MySQL 定向并发/恢复验证；记录测试命令、通过数和跳过项。当前本轮尚未得到这些最终结果时不得宣称生产就绪。
3. 按选定形态实现授权、存储对账、解析部署与运维门槛；用越权、崩溃恢复和备份恢复演练给出证据。
4. 在 M4 前端代码开始前，按既有约定先讨论交互、设计规范和样式。M4 的界面应展示 `partial`、`interrupted`、待人工确认、来源定位及容量限制，不能把未完成显示成正式结论。

可复核的工程说法是：当前是具备事务、幂等、来源审计和受控 Agent 的本地后端，正在向企业部署过渡。是否达到生产级，以所选部署形态下的权限、运维、真实资料质量与恢复演练结果为准。
