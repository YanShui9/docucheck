本步处理单元格文字已读取、但批注或旧式绘图未读取后仍返回 `complete` 的风险。只修改后端 XLSX 解析与离线测试；没有调用模型 API、启动 Docker、安装依赖或修改前端。M2-2 整体仍未验收。

## 第一步：复现误判

生成报价表 `A1=已装内存`、`B1=16 GB`，在 B1 批注中写入“已装内存 32 GB”。旧解析只读出可见单元格，返回 `complete`。进一步构造两种可由 openpyxl 正常读取的 XLSX：保留批注关系但移除 `<legacyDrawing>` 标签的文件，以及页眉使用 `<legacyDrawingHF>` 引用含内存文字图片的文件。旧解析同样返回 `complete`。新增失败测试分别确认三条路径。

## 第二步：修正解析覆盖

`parse_xlsx` 在原有工作表 XML 扫描中识别实际出现的 `<legacyDrawing>` 与 `<legacyDrawingHF>`，记录 `sheet:<工作表名>:legacy_drawing_unverified:<关系 ID>`。它还按工作表实际 part 路径定位相邻的 `.rels` 文件，识别 `comments` 关系并记录 `sheet:<工作表名>:comment_unverified:<关系 ID>`。这能覆盖没有 VML 标签、但仍有可读取批注的文件；单元格证据继续保留。只存在于 ZIP、没有被工作表引用的批注或 VML 资源不会单凭文件名触发问题。

工作表 part 被移至非默认目录时，关系文件跟随该 part 定位，不写死 `xl/worksheets/`。解析版本增加 `/legacy-drawing:1/comments-rel:1`，新快照证据 ID 随版本变化。

## 第三步：离线验证

常规批注、仅有批注关系、页眉图片三类测试先复现旧误判，再验证 `partial` 与工作表级原因。仅有批注关系的测试还覆盖工作表和关系文件重定位；普通无关系工作簿保持 `complete`。后端全套测试 **131/131 项通过**，全目录 Ruff 与 `pip check` 通过。本步没有重新运行真实模型对话。

## 边界与下一步
