# 采购助手上下文、历史回读和原文引用审查

> **已应用本机服务**：代码 `0d5cc19`，API 与四后台源码已同步；[部署证据](repair-assistant-context-audit-2026-10-09-applied-evidence.json)。页面入口 http://127.0.0.1:15173/ 。本次未新增真实模型在线验收。

## 范围和结论

接续用户对“每轮注入北京时间”的纠正，检查普通聊天、动态指标编辑、RAG、会话历史及持久化结果校验。审查基线为 `c4741dc`；下述内容取代上一份分阶段上下文报告中“每轮组装日期”的设计。日期数据本身体积很小，并非此前超限的全部原因；真正需要约束的是每阶段的清单、工具定义、历史和工具结果总量。

本次修复不扩大模型预算、不更换依赖、不修改前端交互。候选仍须用户保存及确认。当前源码验证和服务应用结果分别记录，不能将离线测试解释成真实模型行为验收。

## 发现及修复

| 级别 | 问题和可复现后果 | 实现 |
| --- | --- | --- |
| P2 | 每轮都加入日期，即使采购任务不涉及当前时间 | 普通聊天不读取时钟。有限的纯日期/星期/时间问句由服务器直接回答，模型调用 0；复杂任务由原目录工具扩展为 `read_context(scope=current_time)` 按需读取。服务器转为 UTC+08:00，返回 Asia/Shanghai，不使用历史中的日期冒充现在。 |
| P1 | 检索命中长原文后半段，助手却重新读取开头 800 字节，丢失真正的命中内容 | BM25 与 Hybrid 检索返回来源字符偏移；助手从命中位置回读，并提供 `read_source` 与 `next_char` 分页。引文必须包含于一个实际展示给模型的原文窗口，禁止拼接不连续窗口伪造引文。 |
| P2 | 连续检索不断累计完整工具观察，可能第二/三次模型调用前超限；审计仍显示首轮数值 | 证据阶段只加载所需工具和资料视图，最多保留前一组工具观察。先移除旧观察，再按完整窗口减少当前展示量，明确返回省略 ID；完整已读记录留在服务端。每次预算检查更新实际本轮输入上界，失败也能定位。 |
| P2 | 提示词要求回读历史，但普通 Assistant 没有对应工具及绑定回调 | 接入既有 `MemoryContext.history_reader`，工具参数不能指定用户、Case、会话或快照。回读前后检查权限、历史版本及截止序号；只保留最近一次回读内容，审计记录读取 ID、偏移和摘要指纹。旧聊天仍是非权威上下文。 |
| P2 | 准备修改手机，模型可以把新增指标写到另一个未准备的已有品目 | 新增指标也必须属于准备视图中的品目，或本 patch 合法新增的品目。原有 update/remove 目标检查继续有效。 |

## 数据和兼容边界

- `source_windows` 在既有 assistant JSON 结果中保存 evidence_id、start_char 和精确原文窗口；不改数据库表，不改向量索引或重新 Embedding。
- 新结果再次读取时，重新加载相同快照的原文，并核对偏移、800 字节窗口、引文、来源信息与答复。篡改偏移或文本，即便同步更新 payload digest，也拒绝返回。
- 已有不含 `source_windows` 的旧结果继续按“开头原文”规则验证。**这属于新代码读取旧数据的兼容，不代表旧代码能读取新结果**。产生新结果后若回退，必须保留新字段/窗口校验的兼容读取能力，不能只换回旧镜像。
- 每个来源窗口最多 800 UTF-8 字节；单次主动回读最多 4 个来源，有偏移时只允许 1 个；最多保留 96 个来源窗口，每次只能引用本快照已检索并实际展示的原文。
- 采购清单仍为最多 100 项/20 个品目；一次编辑准备最多 4 个指标/4 个明确品目。复杂单项、过长问题以及总调用/时间耗尽仍会明确中止，不能承诺无限上下文。
- 历史回读只在初始路由阶段提供，编辑和证据阶段的工具集合继续收窄。当前采用已有结构化摘要与有限历史，不在本次增加额外 LLM 摘要费用。
- 简单时间识别只匹配有限的纯时间问句；“根据今天日期整理交期”等采购问题仍走 Agent。可信时间依赖服务器时钟正确。

## 验证过程

1. 六个核心缺陷先编写失败用例，再修复通过。
2. 补充 Hybrid 长原文分页、越界来源拒绝、不连续引文拒绝、原文窗口篡改拒绝、真实失败输入上界审计。
3. API/SQL 流程补充长原文后半段结果保存再读取、篡改拒绝、旧结果兼容，以及同会话历史成功/跨会话拒绝和审计留存。
4. 已有 109 项关联回归通过；新增测试过程中曾因测试夹具使用中文 HTTP 幂等头而失败，改用摘要作为头部后，同/跨会话两项通过。此失败发生在测试请求构造，未进入业务接口。
5. 原十项真实失败请求使用只读 SQL 和脚本 Provider 回放，输入上界 **14601 / 15932**，原十项逐字段保留，新增为十一项。回放开放了历史读取工具定义，真实模型请求及真实业务写入均为 0。

最终完整离线回归 **1338 passed / 41 skipped / 网络尝试 0**，Ruff 与 pip check 通过；独立临时任务的真实 MySQL assistant 回归 **1 passed**，前端 **13 文件 / 172 passed** 与 TypeScript 检查通过。41 项外部集成测试仍按原有显式 opt-in 规则跳过，不计作通过。脱敏[验收证据](repair-assistant-context-audit-2026-10-09-evidence.json)包含源码哈希和输入上界。

12 段较长资料连续检索三次：四次脚本模型请求输入上界为 **6369 / 15269 / 15269 / 15269**；每轮完整展示 9 段，另 3 段给出可回读 ID，持久已读窗口去重为 9 个。此前相同类型请求会在第二或第三轮超限。以上数值是 UTF-8 保守输入上界，不是服务商实际 token 用量。

审查中使用了独立代码审查反馈确认初始缺陷；修复后的验收以本报告的实际测试为准，不声称独立复审已经全部通过。代码验证完成，服务应用结果在下一节单独记录。

## 本机应用与保留核对

- 从各现有运行镜像离线复制应用代码，构建网络关闭，未安装依赖。三组镜像的 82/82/77 个安装包清单与更新前完全相同。
- 更新前及暂停派发后检查 queued/running、待派发、当前快照解析/索引、worker active/reserved/scheduled 和 runs 队列均为 0，再更新 API、worker、indexer、dispatcher、cleaner。
- 四后台各 123 个源码文件，共 **492 个哈希匹配**。环境、证书挂载、网络、用户保持；其余 **14 个容器未重启**。没有数据库迁移或向量重建。
- API 以原 OIDC 配置从 Conda 环境重启，进程 33836。API live/ready 与 15173 页面均 200，直接 API 及前端代理的未登录业务请求均 401，OIDC 元数据 200。
- 两个 waiting_user 的 Run/attempt/fence、五条 ready 索引、文档解析和派发状态保持。原手机任务的清单头、保存/确认操作、Run 与助手候选绑定完整指纹前后一致。
- **实际新 worker** 使用真实 SQL 绑定/历史/摘要及脚本 Provider 只读回放：输入上界 **14601 / 15934**，原十项保持，内存候选十一项；并验证纯日期问题在未提供模型 Provider 时可完成。真实模型、Embedding 请求和真实业务写入均为 0。与宿主回放的 15932 差异来自工具调用 ID 长度。
- 本步未通过浏览器代用户提交新问题、保存候选或执行付费模型。HTTP 健康检查、源码核验和脚本回放分别覆盖各自边界，不能代替线上模型端到端验收。
- 更新前镜像保存在各服务 `pre-assistant-audit-20261009` 标签。已有新格式结果时，回退必须带上 `source_windows` 兼容读取/验证逻辑并通过数据校验；标签本身不是数据兼容保证。
