## 2. 已实现的 M5-B 代码

### 计分器 `evals/m5_metrics.py`

- 按计划 gold 格数计分；失败、未运行、缺项、重复、旧快照、非正式结果和可见答案不一致均不能缩小分母。
- 状态与处理状态分开。危险“满足”逐格计数，部分 Run 的错误可见“满足”也保留。
- 确定性状态的必要证据分母包含满足/不满足/冲突，共89格；冲突须需求及双方。定位要求原件文件名、PDF页码或XLSX表/单元格及对应原文。
- 评分侧读取原件；引用检查定位、原文、哈希及供应商/型号归属。每格合并事实/原因引用中的同一证据ID后计一次；零引用的错误率为null，不当作零错误。额外的合法表头引用允许存在；字段所需的全部依据用必要证据指标检查。
- 证据不足还要求适用原件全部解析完成。损坏的导出记录计失败并保留分母；JSON布尔页码不能冒充整数1。
- 返回逐格失败、混淆矩阵、引用错误和 Agent 任务成功数。所有报告均保留开发验证属性。

### 正式上传执行器 `evals/m5_run.py`

- 默认仅离线预览，不读.env、令牌或创建HTTP客户端；`--send`才访问本机API。
- AI复核与原件/gold哈希不一致、漏格、重复格、伪造人类属性均拒绝准备协议。
- 运行前写入不可覆盖的 `protocol.json`，记录本地Python源码/依赖配置哈希、资料版本、任务、模式与本地预算。输入变化在向API发送前被拒绝，原件上传前再次核对字节和哈希。
- 运行侧只读 `inputs`：新Case、逐个上传原件和角色/供应商/型号、等待该快照解析、创建新会话、提交原问题、等待Run和读取同快照JSON导出。没有 gold 或理由进入HTTP输入。
- 保留首次运行，不自动retry/resume。解析失败不提交模型Run；客户端Run超时或中断会请求取消，取消失败单独记录。创建项目/网络失败和未开始任务仍进入计划分母。
- 取得有效Run ID立即开启取消保护；回执缺失/损坏attempt或轮询返回错Run/快照时取消已接受的目标Run。只在身份全部一致后接受终态并解除保护。
- 每个任务原始观察单独保存，全部结束后才评分。失败Case保留便于复查，不自动删除用户资料。
- `--performance`固定为m5-c01五文件，10次新Case/新会话；重复Case不能计入成功，失败保留在10次分母。

### Run API 用量

`GET /api/v1/agent-runs/{run_id}`新增可选 `model_id` 与 `usage`，来自当前attempt已有的持久化字段，不需要新迁移。usage只返回限定键的非负整数；未知或不合法值不冒充0，不输出配置或凭据。原Case权限保持，另一用户读取仍返回404。

当前API没有完整缓存token分类或已核验价格，因此工具的费用为null并记录原因。协议中的请求/token数量是**当前本地源码的预算上限**，不是预测实际消耗；运行服务的代码/解析器身份仍须在真实测量前核对。

### 真实PDF兼容修复

首跑的MinerU 4.0.7实际输出把纯文本标题、页脚标为`paragraph_title`、`footer`；此前未列入支持类型。页脚说明与准确页码同行，还触发了多列警告。现保留这些纯文本块为证据；只对第一/末条布局行中与当前页及总页数准确匹配的中英完整页码进行分页识别。

混合图片、未知块型、错误页码、正文的列、页脚的多业务列、矢量/图像/注释及原文漏抽检查继续生效。解析版本新增`plain-blocks:2`、`layout-columns:2`，原有解析记录与首跑不回写为完整。同一份真实MinerU输出离线重放为complete，13块、覆盖问题0；两次新Case实时解析的三份原件也全部complete。
