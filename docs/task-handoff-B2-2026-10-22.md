# B2 同采购任务跨对话与版本交接

日期：2026-10-22。基线为 B1 `f37598c`，实现位于隔离分支 `codex/context-request-diagnostics`。本步源码、独立复核和最终离线验收已完成，未合并、推送或部署，不表示运行服务已经更新。

## 行为与边界

同一采购任务开启新对话，或切换资料、清单与关联范围后，Assistant 可获得一份有原消息位置的历史交接：原目标、最近请求、历史处理状态、来源范围、当前范围及变化字段。只从当前问题提交前、同 Case 的不同对话或不同业务范围选取来源，不读取其他采购任务。

交接正文最多 3500 UTF-8 字节。完整原问题放不下时仅保留回读位置；旧摘要按完整条目取舍，只继承目标、未决问题和下一步，不自动继承旧决定。最多捕获两份原始 phase 和八份支持摘要的 phase；因此这不是对所有任务历史的完整搜索。最新来源范围内的最早 phase 被标为历史目标，用户后来可能已改变目标，需要结合最近请求和当前要求理解。

旧待办不会自动成为当前待办，历史指令不能授权新的操作。已确认采购要求、报价和正式结论仍分别读取当前版本的业务记录与原文。交接不会合并未保存的候选清单，不向正式 Dynamic 审查注入历史交接或回读工具；提示约束和来源隔离不等于真实模型语义准确率已经验证。

## 持久化与回读

复用 `conversation_summaries`，新增独立 `task_handoff_v1` 类型，并沿用该对话全局递增版本。不增加迁移或模型调用，不覆盖 B1 语义摘要及旧摘录。

每个 Run 保存一份不可变交接，空历史也冻结。同 Run 的显式 retry 重用原记录，不追入后来产生的历史。保存及回读沿用 Case 锁、权限、版本、attempt/fence、取消与删除校验，并重验原 phase、消息、摘要和冻结指纹。`read_task_history` 仅接收服务端已捕获的消息 ID、内容部分和分页位置，不能指定任意 Case、对话或快照。

manifest 保存记录 ID、版本、来源位置、范围、时间与指纹，不保存历史正文。正文超过本次请求可用空间时，先整体省略交接，再处理旧摘要和历史，不截断当前问题或规则。原对话、旧摘要、旧 Run 和报告继续保留。

## 时间边界补修

独立规格复核发现两项 P2，均先补反例再修复。提交在取得 Case 锁后采集微秒级截止时间，写入首次 queued 事件的 JSON；终态 phase 也在 Case 锁内采时，避免等待锁导致时间倒置。retry 的后续 queued 不替代首次边界，边界参与冻结摘要并在回读时重验。

MySQL 的消息及 Run 时间字段为整秒，默认可能向上舍入，不能用它们与精确截止时间严格比较。来源资格改由微秒级 phase、摘要时间判定；粗时间仅保留在冻结来源指纹中。缺少精确标记的旧 Run 使用根消息整秒值前一秒作为保守下界，可能少带紧邻边界的历史，避免纳入真实提问之后的内容。该兼容策略不宣称旧历史无损。
