# M2-2b：XLSX 工作表范围声明校验（2026-09-26）

本步修正 XLSX 声明的工作表范围未覆盖实际单元格时，只读解析跳过原件内容、却返回 `complete` 的问题。没有调用 DeepSeek、启动 Docker、安装依赖或修改前端。M2-2 的其他覆盖问题和任务级限额仍未完成。

## 已实现

- 解析前完整扫描工作表 XML 的行与单元格坐标，包括未显式写出单元格坐标时的顺序位置。原始行、列超过首版 1,000 行或 30 列上限时立即拒绝，避免重读稀疏超大工作表时产生大量空行。
- 实际单元格落在声明范围外时，记录首个问题位置 `sheet:<工作表>:dimension_mismatch:<单元格>`，重置 openpyxl 的只读范围后再读取全部单元格。恢复的单元格进入带坐标的证据，但文件保持 `partial`，不会据此发布正式缺失或满足结论。
- 原有合并单元格问题继续记录；XML 预扫描不再遇到首个合并单元格就停止。解析版本增加 `/dimension:1`，新快照的证据 ID 随版本变化。

## 离线验收

用真实 XLSX ZIP 内容构造错误范围：原件有 `A1`、`A6`、`B6`，声明分别被改成 `A1` 或 `B6`。原代码漏读单元格并返回 `complete`；修正后可读回 `A6/B6`，记录问题位置并返回 `partial`。另将实际 `AE1` 或 `A1001` 藏在声明 `A1` 之外，解析均按行列上限拒绝。正常模拟报价表仍为 `complete`。

在 `docucheck` Conda 环境执行 `backend/tests`，**117/117 项通过**；全目录 Ruff 与 `pip check` 通过。本步仅做本地离线验证，未重新运行真实模型对话。

## 边界与下一步

范围错误时目前只记录每张表第一个越界单元格，用于定位和阻断错误的完整状态；该表其他越界单元格仍被尝试读取。合并单元格继续标为 `partial`，公式仍拒绝。其他 XLSX 不支持结构的全面覆盖尚待后续小步。

下一小步 M2-2c 处理混合 PDF 的非文字区域：同页有普通正文和图片表格时，当前文字覆盖校验仍可能将漏掉图片的结果标为 `complete`。随后继续 XLSX 其他结构与任务级限额；整个 M2-2 尚未验收。
