# 资料关联弹窗：状态与操作简化

2026-10-21。用户指出原弹窗难以区分已经关联、需要重新关联和正在填写的内容，且“品目原文依据”“SKU”等用语难懂；讨论后授权实施。范围与验证清单见[本轮计划](superpowers/plans/2026-10-21-binding-dialog-clarity.md)。

## 用户可见变化

打开已关联的资料，先看到“已关联”、采购商品和适用文件范围；编辑表单默认收起，并提示可返回对话开始审查。尚未关联、旧关联需要重新确认、历史只读及版本变化分别显示明确状态。旧记录先展示名称和范围供核对，不自动填入当前请求。

“当前生效的关联”和“本次待保存的修改”分开展示。新增、修改、取消各有文字标记和数量汇总；修改同时展示原范围和新范围。取消先产生待保存项，原关联仍显示，可撤销；只有明确勾选并保存后才提交。保存请求继续保留其他文件的关联及所有版本、范围和幂等约束。

常用表单改成“采购商品”“使用文件中的哪些内容”“文件哪里写明了商品名称”和“引用内容”。具体型号或货号、上传时填写的信息、详细原文和确认记录按需展开。上传时未填写旧标识就不展示分类，不替用户推断其含义。单商品声明、名称依据的原文校验、修改说明与最终确认仍保留。

未保存的填写在关闭或手动刷新前会提示；继续编辑保留输入。正在编辑一条时，其他行的操作暂时禁用，避免未暂存内容被覆盖。弹窗内容独立滚动，底部保存区保持可见；确认离开时原内容暂时不可交互，焦点进入提示按钮。

## 不确定结果与失败边界

- 保存中不允许关闭。没有发出请求时才称“尚未生效”。
- 网络中断导致结果未知时，提示“请求可能已经保存”。原区域改为“保存前读取的关联”，提交内容标为“保存结果待核实”，不能编辑或撤销；可读取服务器记录，或重试相同请求体和幂等键。
- 未知结果下刷新失败，只有请求代次仍相同且没有权限拒绝时才恢复冻结请求；权限失效会停止编辑，旧刷新晚到也不能把旧草稿和重试权限恢复到新版本。
- 收到成功回执但随后读取失败，不再展示旧关联为当前状态，也不再次发送写请求；提示已保存并要求刷新核对。无未保存内容时可正常关闭。
- 仅当前资料快照及已确认清单身份匹配时展示当前生效关联；历史只读不宣称可用于当前审查。
